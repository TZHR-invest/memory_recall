# 记忆去重性能成本分析报告

## 一、去重流程成本分析

### 1. 哈希检查

**实测结果**（基于实际测试）：
- **SHA256 计算**：0.02 ms（本地计算，极快）
- **数据库查询**：2-4 ms（简单索引查询，`SELECT id FROM memories WHERE content_hash = ? AND status = 'active' LIMIT 1`）
- **总成本**：**低**（约 2-5 ms）

**成本评估**：
- ✅ **优点**：速度快，准确度高（完全相同内容）
- ✅ **数据库开销**：低（索引查询，O(1) 复杂度）
- ❌ **缺点**：只能检测完全相同的内容，无法检测语义相似

**适用场景**：
- 短文本（< 100 字符）
- 快速过滤已知重复内容

---

### 2. 向量相似度检查

**实测结果**（基于实际测试）：
- **Embedding 生成**：180-210 ms（调用火山引擎 API）
- **向量搜索**：5-18 ms（PostgreSQL 向量索引查询，`ORDER BY embedding <=> ? LIMIT 1`）
- **总成本**：**中**（约 200-230 ms，主要耗时在 API 调用）

**成本评估**：
- ✅ **优点**：准确度高，能检测语义相似内容
- ✅ **数据库开销**：中等（向量索引查询，O(log n) 复杂度）
- ❌ **缺点**：速度慢（依赖外部 API），有 API 调用成本

**适用场景**：
- 长文本（>= 100 字符）
- 需要检测语义相似的场景

---

### 3. 混合检查（哈希 + 向量相似度）

**实测结果**：
- **哈希命中**：2-5 ms（跳过向量检查）
- **哈希未命中**：200-230 ms（执行向量检查）
- **平均成本**：取决于哈希命中率

**成本评估**：
- ✅ **优点**：兼顾速度和准确性
- ✅ **适应性**：根据实际情况自动调整
- ❌ **缺点**：两步检查，逻辑稍复杂

**适用场景**：
- 通用场景（推荐）
- 需要平衡性能和准确性的场景

---

## 四、优化建议

### 1. 按文本长度选择去重策略

**建议**：
- **短文本（< 100 字符）**：仅使用哈希检查
  - 成本：2-5 ms
  - 准确度：高（完全相同）
  - 理由：短文本语义变化大，向量相似度意义不大

- **长文本（>= 100 字符）**：混合检查（哈希 + 向量）
  - 成本：2-230 ms
  - 准确度：高（语义相似）
  - 理由：长文本语义丰富，需要向量相似度判断

**实现建议**：
```python
async def _check_duplicate_optimized(self, content: str, embedding: Optional[List[float]], user_id: str) -> bool:
    # 短文本：仅哈希检查
    if len(content) < 100:
        content_hash = self._calculate_content_hash(content)
        return await self._check_duplicate_by_hash(content_hash, user_id)
    
    # 长文本：混合检查
    return await self._check_duplicate(content, embedding, user_id)
```

---

### 2. 批量创建优化

**当前问题**：
- 批量创建时，每条记忆单独生成 Embedding
- 总耗时与记忆数量线性相关

**优化方案**：

#### 2.1 批量生成 Embedding

```python
# 使用 embed_batch 一次性生成多个 embedding
embeddings = embedding_client.embed_batch(contents)
```

**优势**：
- 减少网络往返次数
- 提升 API 吞吐量

#### 2.2 并行去重检查

```python
# 并行执行去重检查
tasks = [self._check_duplicate(content, embedding, user_id) for content, embedding in zip(contents, embeddings)]
results = await asyncio.gather(*tasks)
```

**优势**：
- 减少总耗时
- 充分利用数据库并发能力

---

### 3. 缓存优化

**当前实现**：
- 已实现 Embedding 缓存（`cache_manager.get_embedding(text)`）
- 避免重复调用 API

**建议增强**：
- **缓存命中率统计**：监控缓存效果
- **缓存过期策略**：定期清理过期缓存
- **缓存预热**：提前加载常用内容的 Embedding

---

### 4. 相似度阈值调整

**当前阈值**：0.94（相似度 >= 94% 认为是重复）

**建议**：
- 根据实际业务需求调整阈值
- **高精度场景**：提高阈值（0.96-0.98）
- **高召回场景**：降低阈值（0.90-0.92）

**实现建议**：
```python
# 允许用户自定义阈值
async def _check_duplicate_by_embedding(self, embedding: List[float], user_id: str, threshold: float = 0.94) -> bool:
    # ... 查询逻辑 ...
    if similarity >= threshold:
        return True
```

---

### 5. 数据库索引优化

**当前索引**：
- `content_hash` 字段：B-tree 索引
- `embedding` 字段：向量索引（IVFFlat 或 HNSW）

**建议**：
- 定期维护向量索引（`VACUUM ANALYZE`）
- 根据数据量选择合适的向量索引算法：
  - **小数据量（< 10 万条）**：IVFFlat
  - **大数据量（>= 10 万条）**：HNSW
