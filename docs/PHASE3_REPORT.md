## 一、完成情况

### ⚠️ 重要修正：移除场景自适应提取

**原因**：场景判断应该是**召回时的任务**，不是存储时的任务

| 阶段 | 任务 | 说明 |
|------|------|------|
| **存储时** | 实体提取 + 关系推理 | 不需要场景判断 |
| **召回时** | 向量搜索 + 语义匹配 | 用户问题决定需要什么 |

**修正内容**：
- 移除 `EXTRACT_ENTITIES_WITH_SCENARIO_TOOL`
- 移除 `SCENARIO_AWARE_EXTRACTION_PROMPT`
- 移除 `_extract_entities_adaptive` 方法
- 简化 `build_graph` 流程
- 保留智能确认服务和软过滤服务

### 任务 1: 智能确认服务 ✅

**目标**：避免错误累积，新实体、低置信度、关系冲突时需要用户确认

**完成内容**：

1. **服务实现**（`confirmation_service.py`）
   - 实现 `ConfirmationService` 类
   - 实现确认阈值配置
   - 实现待确认队列（内存存储）

2. **核心方法**
   - `should_confirm()`：判断是否需要确认
   - `send_confirmation()`：发送确认请求
   - `handle_response()`：处理用户回复
   - `get_pending_confirmations()`：获取待确认列表

3. **确认场景**
   - 新实体首次出现（置信度 < 0.8）
   - 置信度过低（置信度 < 0.6）
   - 关系冲突检测

4. **关系冲突检测**
   - 定义冲突的关系类型映射
   - 检测同一实体间的矛盾关系
   - 示例：friend vs colleague, likes vs dislikes

**测试结果**：

- 通过数：5 个
- 通过率：100%

**验收标准达成情况**：
- ✅ 可以正确判断是否需要确认
- ✅ 可以生成确认请求
- ✅ 可以处理用户回复
