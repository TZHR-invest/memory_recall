# Crystal 专项产品需求（PRD v1 · 草稿）

> 状态: 草稿 · 系统: crystal · 版本: v1 · 最后更新: 2026-08-16
> 关联: [目标模型](foundation.md)（语义裁判）· [里程碑](milestone.md)（能力范围/节奏/流程）·
> [迁移路径](migration-path.md)（工程阶段）· MR-006 / MR-011
> 定位: 本文是 crystal 专项的**需求层**文档——用户故事、角色、能力验收（用户可感知的"完成"）。
> 与语义层（v1）、工程层（migration-path/milestone）互补；本文不写实现方案（归各 design v1）。

## 0. 一句话

**把"文本 + 手工标志位的记忆大杂烩"（v5 `memories`）升级为两层目标模型**
（**Evidence 不可再生证据 → Claim 派生主张 → Lineage Edge 演变**），
以命名空间隔离（`crystal.*` + `/api/v2`）**渐进接管、不爆破 v5**；
一期交付"证据采集 → 对账 → 状态查询召回 → 个人工作台（裁决+洞察）"，价值引擎二期再喂数据。

## 1. 角色与原则

| 角色 | 需求视角 | 一期? |
|------|---------|-------|
| **开发者（自托管主用户）** | 跨会话记住项目事实/决策/偏好；能看到并纠正系统记住了什么；**用自己数据洞察记忆效果** | ✅ 主角 |
| **高级用户（未来）** | 借洞察面调整召回/注入策略配置 | 策略工作台暂不建设，洞察先行 |
| **admin（运维）** | trace/embedding 日志级调试、迁移/退役操作 | ✅（权限分离，不占主场景） |

- **北极星**：系统记住/召回的东西长期净价值最大；价值 = 复用机会 × 有效性 × 影响 − 维护成本；**错误信息按负价值计**。
- **不静默丢弃**：任何截断/排除都对用户可见（MR-017 教训直接进需求）。
- **隐私最小化**：洞察只用开发者自己的个人数据，不用他人/全量数据做 debug。
- **个人 key + API**：裁决/洞察核心能力走 API（插件也能调），web 工作台是可选管理层。

## 2. 用户故事（一期，按能力支柱）

### 支柱一：证据层（写侧的输入）

- **US-E1**（P0 add 自报）：作为开发者，我在会话里说"记住：正式规划文档是 docs/PROJECT_PLAN.md"，
  以便下次不用重新解释。→ 该观察成为一条 **Evidence**（ms 级落库，不可变），后续对账异步推进。
- **US-E2**（状态可追踪）：作为开发者，当一条新记录处理失败（embedding/对账出错），
  我需要知道它卡在哪一步，而不是静默消失。→ `evidence_processing` 状态机（pending/processing/done/failed + 步骤名）。

### 支柱二：对账（写路径）

- **US-R1**（结论引用证据）：作为开发者，我召回一条结论时能点开"它的证据是什么"，
  以便判断这话还该不该信。→ Claim 引用 1..N Evidence（`claim_evidence`），不变量"结论必须引用证据"。
- **US-R2**（纠正不丢历史）：我纠正一条过时结论（如"开发文档是 development-plan.md"→ 实为 PROJECT_PLAN.md），
  旧结论不消失、生成带 reason 的 supersede 边，无需人肉改 `is_latest`。
- **US-R3**（特权纠正）：用户显式纠正 = 特权 Evidence（`source_kind=user_correction`），
  对账**直接 supersede** 现有 Claim，不走 LLM 推理——保证"用户说了算"。
- **US-R4**（冗余累积要收敛）：同一事实反复出现时系统应合并/强化（reinforce），
  而不是无限堆积近似重复（hermes 累积冗余的教训：semantic_dedup 0.85 只去近似重复）。
  强化计数走 **content 计分规则**（[v1 §置信度与价值信号](foundation.md#置信度与价值信号单轴--离散统计)：独立性闸门 + 证据强度分档 + 派生折扣 + 负向通道）；
  **被使用（report_effect）不算 reinforcement，只喂复用/outcome**。

### 支柱三：状态查询（召回）

- **US-S1**（回当前为真）：新会话注入返回"**当前为真**的 Claim"（scope + active 预过滤），
  不是"相似度最高的文本"——过时结论不因相似度高而混进来。
- **US-S2**（召回可解释）：我看到"为什么召回这条、为什么砍掉那条"（粗排全展示 + 精排分数 + 截断逻辑），
  以便判断系统质量、发现数据问题。→ 洞察面契约（与支柱四平级，非附属）。

### 支柱四：个人工作台（MR-011）

- **US-W1**（裁决面·浏览/纠错/遗忘）：作为开发者，我在个人工作台看到自己记了什么，
  可确认（+Δ 置信）/ 纠错（= 特权 Evidence）/ 遗忘（retract），只被授权看自己 owner 的数据。
- **US-W2**（审计面·scope 提权）：系统建议"这条项目内知识可提为全局知识"（S1 质变），
  我**事后审计**决定采纳与否（scope 提权 = 系统主动 + 用户审计）。
- **US-W3**（审批面·owner 提权，P1）：系统建议"这条个人知识提升为团队共享"，
  我**事前审批**决定放行（owner 提权 = 系统建议 + 用户审批）。团队 owner 是一期之后（P1）。
- **US-W4**（洞察面·统计）：我查看记忆/claim 的统计（价值信号分布、source_kind 构成、拓扑），
  对记忆效果有来自个人的洞察——**与裁决平级的一等能力**。
- **US-W5**（洞察面·召回复盘）：每次召回像 trace 一样摊开：粗排全部候选、精排每个因子分数、
  截断/排除项（cap 砍了哪几条）；低置信项**只标注不静默丢弃**。

### 迁移与退役

- **US-M1**（一次性全量迁移）：我主动触发旧 `memories` → `evidence` 迁移，幂等可重放，
  迁移后对账重新生成 claim。系统**不自动迁移**（迁移结果需人工审一遍）。
- **US-M2**（四端切换）：opencode/dsh/hermes/deepseek-tui 各自切 `/api/v2`，期间可回退，v5 不中断。

## 3. 能力验收（用户可感知，方向性；逐条在对应 design v1 展开为可勾选清单）

> 每条 = "用户能看到/做到什么"；实现时在对应 design v1 的验收标准里细化为可测试条目。

| # | 能力 | 验收（用户视角） |
|---|------|-----------------|
| A1 | 证据采集 | 写一条 evidence → 落库 → 对账自动生成/更新 claim；失败可见（卡在哪步） |
| A2 | 结论溯源 | 每条召回 claim 能点开证据；evidence 引用 1..N 且不可变 |
| A3 | 纠正闭环 | 纠正旧结论 → 旧结论不丢 + 生成带 reason 的 supersede 边，无需人肉改 `is_latest` |
| A4 | 状态查询 | 召回返回"当前为真"（active + scope 匹配），过时/被取代的结论不混入 |
| A5 | 召回可解释 | 每次召回能看到粗排全貌 + 精排分数 + 截断项；无静默丢弃 |
| A6 | 裁决面 | 个人 key 只看自己的数据；确认/纠错/遗忘生效且可追溯 |
| A7 | 审计面 | scope 提权建议可见、可审计采纳/拒绝 |
| A8 | 洞察面 | 统计 + 召回复盘可用，只用个人数据 |
| A9 | 迁移 | 一次性迁移幂等可重放；迁移后 claim 关联正确（抽样核对） |
| A10 | 切换/退役 | 四端切 /api/v2 后无旧路由调用；满足退役标准才 DROP 旧表，可回退 |
| A11 | 权限隔离 | admin debug 链路（trace/embedding 日志）与个人工作台（owner 数据）互不混淆 |

## 4. 范围（一期 In / Out）

> **本表是范围决策的权威源**（用户视角需求：做什么/不做什么）；milestone §5 是执行映射，只承接指针，不重复维护清单（避免双份漂移）。

**一期（M1–M5）**：证据采集(P0) + 对账 + 状态查询召回 + 裁决/洞察工作台 + 旧数据迁移 + 四端切换 + v5 退役流程。

**进 crystal 完整项目、非一期**：

| 项 | 决策 | 状态 |
|----|------|------|
| 价值引擎遥测（复用频率 / outcome，P1） | 一期后喂数据 | 推后 |
| B4 投毒 guard（破坏大量 claim → 预警 + 暂停 + 裁决页再确认） | 证据处理流 guard | crystal 完整项目 |
| B3 每日自省（低峰期定时跑，峰谷定价降成本） | 显式触发先行，稳定后加定时 | 推后 |
| 团队 owner（P1） | 个人 owner(P0) 先行 | crystal 完整项目 |
| owner 审批面（US-W3） | 依赖团队 owner P1 | 推后 |

**明确不做 / 暂缓**：

| 项 | 理由 |
|----|------|
| 衰减曲线落库（B1） | 只在召回精排现算，初始恒等，发现问题再激活 |
| 低置信召回策略（B2） | 洞察面数据足够后再定；不静默丢弃是底线 |
| 命名漂移（MR-010） | 主线名 "Memory Recall" 不变；crystal 只作专项代号 |
| MR-017 注入 cap | 仅 v5 有效，非 crystal 契约（crystal 重设计粗排） |
| Entity/主题 / MR-009 合并 | P2 可选附属，随 Entity 构建再定 |
| 策略工作台（高级用户调配置） | 洞察先行，暂不建设 |
