## 1. 数据库：PostgreSQL + pgvector

### 选择理由

1. **统一数据管理**：
   - 关系型数据（记忆、人物档案）与向量数据（embedding、人脸特征）存储在同一数据库
   - 简化架构，降低运维复杂度

2. **成熟稳定**：
   - PostgreSQL 久经考验，社区成熟
   - pgvector 扩展稳定，性能良好

3. **功能完备**：
   - 支持向量相似度搜索（余弦距离、欧氏距离）
   - 支持索引加速（HNSW、IVFFlat）
   - 支持 JSONB 存储（灵活的元数据）

### 成本分析

| 项目 | 费用 |
|------|------|
| 软件授权 | 免费（开源） |
| 服务器成本 | 约 ¥100-300/月（云服务器，视配置而定） |
| 存储成本 | 约 ¥0.3/GB/月 |
| 运维成本 | 需自行维护，或使用托管服务（RDS 约 ¥300-1000/月） |

**总成本**：约 ¥100-1300/月（视部署方式而定）

### 替代方案对比

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **PostgreSQL + pgvector** | 统一存储、成熟稳定、成本低 | 向量搜索性能不如专业向量库 | ✅ **选择** |
| Pinecone | 专业向量库、性能强、免运维 | 仅支持向量存储、成本高、数据分离 | ❌ 成本高 |
| Milvus | 开源向量库、性能强 | 需要单独部署、运维复杂 | ❌ 架构复杂 |
| Weaviate | 开源向量库、内置嵌入 | 功能过多、学习成本高 | ❌ 过于复杂 |

## 3. 人脸识别：face_recognition（本地）

### 选择理由

1. **免费隐私**：
   - 完全本地运行，无需上传图片到云服务
   - 保护用户隐私，数据不出本地

2. **离线可用**：
   - 无需网络连接
   - 适合隐私敏感场景

3. **简单易用**：
   - API 简单直观
   - 文档完善

### 成本分析

| 项目 | 费用 |
|------|------|
| 软件授权 | 免费（开源） |
| API 调用费 | 免费 |
| 计算资源 | 使用本地 CPU/GPU（已包含在服务器成本中） |

**总成本**：**免费**

### 模型规格

| 参数 | 值 |
|------|-----|
| 库名称 | face_recognition |
| 特征维度 | **128 维** |
| 检测模型 | HOG（快速）/ CNN（准确） |
| 识别准确率 | 约 99.38%（LFW 数据集） |
| 依赖 | dlib |

### 替代方案对比

| 方案 | 维度 | 价格 | 准确率 | 隐私 | 结论 |
|------|------|------|--------|------|------|
| **face_recognition** | 128 | 免费 | 99.38% | ✅ 本地 | ✅ **选择** |
| insightface | 512 | 免费 | 99.77% | ✅ 本地 | ⚠️ 可选升级 |
| 百度人脸识别 API | 512 | ¥0.003/次 | 99.9%+ | ❌ 云端 | ❌ 成本高 |
| 腾讯云人脸识别 | 512 | ¥0.0025/次 | 99.9%+ | ❌ 云端 | ❌ 成本高 |

**选择 face_recognition 的原因**：
- 免费：无需 API 调用费
- 隐私：数据不出本地
- 简单：API 易用
- 够用：准确率满足需求

**后续可升级 insightface**：
- 如需更高准确率
- 如需 512 维特征向量

## 技术栈决策记录

### 2026-03-19: 技术栈确认

**决策**：确认使用以下技术栈
- 数据库：PostgreSQL + pgvector
- 向量模型：doubao-embedding-vision-251215（火山引擎）
- 人脸识别：face_recognition（本地）
- LLM：doubao-seed-2-0-pro-260215（火山引擎）
- 后端框架：FastAPI
- 部署：Docker Compose

**理由**：
1. 火山引擎统一 API，简化架构
2. 成本低廉，月费用约 ¥0.8（LLM）+ ¥0.7（Embedding）
3. 人脸识别免费隐私，数据不出本地
4. PostgreSQL + pgvector 统一存储，架构简单

**影响**：
- 向量维度从 1536 改为 **1024**
- 人脸特征维度为 **128**
- 数据库 schema 需要调整
