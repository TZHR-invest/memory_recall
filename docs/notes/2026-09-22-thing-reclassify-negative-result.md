# thing 重分类：实测否决（负结果）+ review 挖出的真问题（同名多型碎片化）

> 状态: DONE（**未执行**）· 日期: 2026-09-22 · 结论: 不做重分类；**真正值得做的是"实体去重/合并"**

## 起因

`thing` 有 18,831 个（占实体 68%），想按今天新增的 9 类技术类型重新归类。

## 第一步：体检（决定"值不值得"）

| 指标 | 数值 | 含义 |
|---|---|---|
| `thing` 总数 | 18,831 | — |
| 有记忆链接 | **18,745（100%）** | 图谱正在使用，不是垃圾 |
| 孤儿 | 84（0.4%） | — |
| 会被今天的过滤规则判垃圾 | **11（0%）** | 过滤规则不认为是垃圾 |
| 去重后唯一名字 | 17,110 | 几乎无去重空间 |

头部全是高价值技术实体：`A股`170链接、`WSL`120、`QMT`108、`O1/O2/O3`、`dsh`93、`cron`91、`trade-pc`87、`tailscale`70、`devbox`69、`Windows`66。
链接分布：`links≥20` 91 个 / `10-19` 158 / `5-9` 488 / `2-4` 2814 / **`=1` 15,280（占实体 81%、链接 49%）**。

**前提**：`entities.type` **不参与召回**（全仓唯一消费点＝类型归一化；另有 `/graph` 的类型筛选与 stats 展示）
⇒ 重分类收益是**面板/分析可读性**，与检索质量无关。

## 第二步：review 发现两个硬约束（原方案据此收窄）

1. **`type` 属于实体身份键**：`entities` 上有 `UNIQUE(name, type, container_tag)`，且
   `_store_entity_graph` 是按 **(name, type, container_tag) 三元组** get-or-create 的
   ⇒ 把某行改成"已存在同容器同名的另一类型"会**违反唯一约束**（UPDATE 直接失败）。
2. **图谱已碎片化（真问题）**：全库 **424 组同名多型**（856 行、3,731 条链接，组均 8.8、最大 177）
   —— 例如 `a股` 同时存在 event+location+organization+thing 四个节点，`dsh` 是 organization+person+thing。
   同一个实体的链接被拆到多个节点 ⇒ **实体图遍历从任一节点都只能覆盖一部分记忆**。

head（links≥5，737 个）里：**651 个无同名兄弟**（可安全改）、**86 个有兄弟**（改了会撞约束）。

## 第三步：两次实测分类 + 独立盲评（都被门槛拦下）

工具 `scripts/reclassify_entities.py`：两遍分类取一致 → 抽样 25-30 条交 `Qwen3.7-Max` 盲评 →
**准确率 ≥85% 才允许写库**，未达标直接中止且不写任何行。

| 轮次 | 上下文给法 | 两遍一致且非 thing | 盲评准确率 | 结果 |
|---|---|---|---|---|
| 第 1 轮 | 最近一条关联记忆的前 160 字 | 415/651 | **58%**（15 合理 / 11 不合理 / 4 无法判断） | ❌ 拒绝写库 |
| 第 2 轮 | 优先取**含实体名**的记忆（ILIKE），否则回退；并要求"证据不足就保持 thing" | 147/651 | **45%**（10/12/3） | ❌ 拒绝写库 |

**失败主因不是"类型难分"，而是"证据不足"**：约 3/4 的不合理判定是"片段里没出现这个实体"
—— 大量实体在记忆里是**别名形态**（库里叫 `CPI`，记忆里写"美国CPI"），单条片段给不出依据；
少数是真歧义（`EMQuantAPI` 该算 software 还是 protocol、`KR2`/`O1:KR3` 是 OKR 编号不是概念）。

**数据库 0 行改动**（复核：`thing` 全局 18,831 / 面板口径 17,614 不变；未生成备份文件）。

## 结论与建议

1. **不做重分类**：错标（45-58% 准确率）**比粗标更糟** —— `thing` 只是"不够细"，标错会把语义搞反；
   而收益本就不影响召回。新写入已经按新 prompt 正确分类（今日自然增量为证），无需回头补。
2. **真正值得做的是"实体去重/合并"**（review 挖出，需单独决策）：
   - 规模：**424 组 / 856 行 / 3,731 条链接**；合并后行数 −432
   - 收益：**一个节点持有并集** ⇒ 实体图遍历能覆盖更多记忆（对 `max 177 链接` 那类大组尤其明显）；
     顺带让 `thing` 等类型的计数回归真实
   - 风险：要搬 `memory_entities` / `chunk_entities` / `entity_relations`（可能产生重复链接与自环），
     必须带备份 + 前后计数校验；属于**数据迁移**，不是改标签
3. 工具留档：`scripts/reclassify_entities.py`（dry-run 默认 / 两遍一致 / 盲评门槛 / 备份 / `--rollback`）。
   **即使不做本次重分类，"先评测、达标才写库"这个结构值得复用到任何数据改写任务** ——
   这次它成功地阻止了 415 行错误标注入库。
