# 2026-08-14: 个人 vs 团队/项目边界 与 知识库 vs 记忆系统

> 类型: 讨论 · 日期: 2026-08-14
> 关联: MR-006（知识对象，预留归属字段）· MR-019（蒸馏桥接）· ADR-0001（定位收敛）
> 重定位: 已并入 [命题晋升总纲](2026-08-14-proposition-promotion.md)（S4 归属迁移），讨论改走总纲主线

## 背景

用户当前 3 人团队、项目少，项目级通用知识已通过 docs/ + git + agent.md 约束落文档共享。
困惑：Memory Recall 是否/何时需要"团队/项目共享记忆"？"知识库"与"记忆系统"的边界在哪？
用户倾向聚焦个人记忆库，但希望厘清长期愿景与需提前预留的点。

## 讨论要点

- **知识库 vs 记忆系统边界（拟采纳，待拍板后升 ADR）**：
  > 慢知识进知识库（docs / git / agent.md 约束——团队共享、版本化、显式、稳定），
  > 快记忆进 Memory Recall（个人 / agent——自动沉淀、易变、可遗忘）；
  > 桥接单向——知识库可蒸馏进记忆（MR-019），记忆不反向污染知识库。

- **现在聚焦个人，正确，别纠结**：团队共享记忆的真实痛点（多人并发、知识不对齐、人走茶凉）
  当前（3 人、项目少）一个不占；想清楚 = 过度设计（写冲突、合并、多来源置信加权、共享权限
  全用不上）；
- **两处预留（成本极低，趁 MR-006 定知识对象时做，不做后面要拆表）**：
  1. "归属"显式化为 `owner(人) × project` 两个正交维度，别把 container 语义焊死成单维度；
  2. 加 `visibility/scope` 占位字段（personal / project）。

## 结论

暂无正式决策。边界句标记"拟采纳"，拍板后升 ADR；当前聚焦个人视角，团队共享暂不做（仅预留）。

## 下一步

1. 拍板边界句后落 ADR（`docs/decisions/NNNN-personal-vs-shared-boundary.md`）；
2. MR-006 设计时把 `owner × project` + `visibility` 预留纳入字段规划；
3. 团队共享（写冲突/合并/置信加权）明确推迟，不进当前路线图。

## 未决问题

- visibility 字段是 personal/project 二值，还是更细（shared-by-team 等）；
- 多来源置信加权（"别人记的 vs 我记的"）将来如何与 confidence 模型（见
  [memory-confidence](2026-08-14-memory-confidence.md)）衔接；
- 知识库→记忆蒸馏（MR-019）是否/如何立项，是单向桥接的唯一实现路径。
