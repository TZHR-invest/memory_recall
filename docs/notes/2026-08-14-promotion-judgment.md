## 背景

外部调研 round-01（五平台）完成，产出了候选判据对照表、价值公式 `value ≈ P(未来还会被需要) ×
C(再获取成本)`、四类失效防护。本 note 记录调研结论回主线后的第一轮讨论：把判据重组为"四桶"
（价值/触发/去向/安全门），并就触发/去向/安全门与用户逐点对辩；同时记录用户对调研方向的不满与重启。

## 讨论要点

### 1. 价值（P×C）——接受，且被锐化
- 调研结论：价值 ≈ P × C，核心指标 Expected Avoided Reacquisition Cost；P 代理 = 复用频率 / 未来相关性 /
  意外性 / 可迁移性，C 代理 = 重新输入或重新查推的成本。
- 用户认可，并确立一条工程原则：**即便只用 LLM 估 P 和 C 两个数，也比直接估"价值"一个数靠谱**
  （分解后再估，优于直接估乘积）。
- 状态：方向接受；P/C 的具体代理信号与阈值待定（无文献值，需产品数据学）。

### 2. 触发——发现系统缺口：无"命中率"回收
- 现状触发渠道只有 add（写入）与 search（召回）两个时点。
- 缺口：召回结果给了用户，但**系统没有回收"命中率 / 是否被采用"的通道**；因此"复用频率"这类行为
  信号目前没有可靠输入源，自动晋升缺数据。
- 用户对"意外"的界定：新命题与系统内已有命题产生**逻辑冲突**。
- 结论：在补齐召回反馈闭环前，复用计数不可靠，自动晋升暂不可行。

### 3. 去向——待拆维度
- 调研结论：项目内 vs 跨项目不是价值差异，是去向差异；区分信号 = 依赖足迹（剥离本项目实体后是否仍成立），
  判定大概率需 LLM 做逻辑分析。
- 用户对"去向"的定义：命题本身是否关联项目、切换项目后是否依旧有效。
- 用户追问（未决）："去向"指**读写权限归属**（谁能读写）还是**适用条件关联**（是否绑定项目上下文）？
  这触到此前已拆的一对正交维度：归属（access control）vs 适用条件（applicability）；调研把两者
  混在一个 "scope" 里，需拆开回答。

### 4. 安全门——挂起
- 调研提出：四类失效（一开始就错 / 过时 / 反复摘要失真 / 投毒）防护机制不同，不能共用一个 confidence 分。
- 用户明确：概念可接受，但**当前方案没有直觉信任，判断不了怎么做**，暂挂起。

## 结论

- 价值 P×C 分解：方向接受 + 确立"分解后再估"原则；细节未拍板。
- 触发：确认存在"无命中率回收"系统缺口；补齐前行为信号不可靠、自动晋升不可行。
  →（2026-08-14）该缺口已被 Q2 调研（reuse-feedback-signals）接住并定性为"缺 outcome 遥测"，
  回主线后拍板为独立 **S-pre**（遥测基座），见 [总纲](2026-08-14-proposition-promotion.md) 结论。
- 去向 / 安全门：未决。
- 调研 round-01 被用户判为"预设了方向和角度，不满意"，已重新发起调研。
