# 2026-08-14: 记忆确信度（confidence）模型讨论

> 类型: 讨论 · 日期: 2026-08-14
> 关联: MR-011（知识浏览/纠错）· MR-017（注入 cap）· ADR-0009（记忆维护闭环）·
> [memory-layering-and-recall](2026-08-14-memory-layering-and-recall.md)（confidence 是分层晋升的输入）

## 背景

当前记忆系统**写入即生效**：`process_memory_async` 自动异步写入 + `semantic_dedup` 去重，无"确信度"概念。
`is_static` 暗含"永久 vs 动态"的确定性，但它只是**性质分类**，不是确定性度量。
用户提出：写入时 LLM 给出信心、召回时信心作参考参数、浏览/确认队列里用户确认可提升确信度、支持人工编辑。
本文记录讨论要点与倾向。

## 讨论要点

- **LLM 自报信心不可当概率**：模型普遍过度自信、校准差；应作**相对排序信号**，非绝对概率；
- **真正确定性由后续信号累积**：复用次数、用户确认、跨 session 稳定复现，而非一次 LLM 自报；
- 四个动作串成自洽模型：

| 动作 | 对确信度的作用 | 语义 |
|------|--------------|------|
| 写入 | 给初值 | LLM 自报 + 规则修正（来源加权：显式"记住 XX" > 自动提炼；static 事实 > 动态事件） |
| 召回 | 排序软因子 + 低置信阈值 | **不允许静默丢弃**（MR-017 教训：cap 静默丢弃已被否） |
| 确认 | +Δ 或锁到 1.0 | 用户背书是最高信号 |
| 编辑 | 新版本 + 提置信 | 更强的"确认 + 修正" |

- **时间衰减需纳入**（与分层联动：近期记忆置信自然高、随时间衰减，长期记忆靠确认维持）；
- **与 is_static 关系**：性质分类（is_static）与确定性度量（confidence）正交但相关——
  static 事实应天然获得置信加成，避免出现两套"确定性"概念。

## 结论

暂无最终结论。方向认可，待细化字段语义 / 初值规则 / 衰减曲线后落 ADR。

**已拍板（2026-08-14，Q2 调研回主线）**：「置信度」拆成正交两轴，取代原先"单一标量"的倾向——

- **内容置信度**（content posterior）：correctness / staleness / harmfulness——这条记忆"对不对/过没过时/有没有害"；
- **复用置信度**（retrieval posterior）：P(useful|M,C)——这条记忆"在上下文里用了有没有用"；
- 两轴对应 v2 判据里两个不同因子，**由证据累积推导**（Beta-Bernoulli），写入时不再一次性设死；冷启动一律 UNKNOWN。
- "内容内部不细分（事实性/稳定性/时效性仍留单一值）"的避过度设计原则**继续保留**——拆分发生在"内容 vs 复用"这一层，不发生在内容内部。

## 下一步

1. 与"记忆分层"一起设计——confidence 是 L1→L2 晋升与衰减的输入之一；
2. 落地依赖：工作台（可见/可纠）+ trace 可解释，三者绑定，缺一不先上（见
   [workbench-vs-debug-roles](2026-08-14-workbench-vs-debug-roles.md)）；
3. ~~倾向先做单一标量 `confidence`~~（2026-08-14 已改）：改为**两轴两字段**——`content_confidence` + `reuse_confidence`；
   内容内部仍单一值（事实性/稳定性/时效性不细分），复用轴由使用/结果遥测（S-pre）喂证据，避免过度设计。

## 未决问题

- LLM 自报信心的初值如何规则修正（来源权重的具体取值）；
- 衰减曲线形态、与"遗忘"接口如何衔接；
- 低置信记忆的召回策略（阈值截断 vs 降权排序）及 trace 展示方式；
- 与 is_static 的字段级关系：confidence 是新列，还是 is_static 派生。
