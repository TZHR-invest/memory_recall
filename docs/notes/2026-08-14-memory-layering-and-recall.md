# 2026-08-14: 记忆分层（近期/长期）与任务级上下文恢复讨论

> 类型: 讨论 · 日期: 2026-08-14
> 关联: MR-006（单一事实源）· MR-017（注入 cap）· MR-019（文档→记忆蒸馏）· ADR-0010（文档 RAG 移出）·
> [memory-confidence](2026-08-14-memory-confidence.md)

## 背景

用户认为需要区分"近期记忆"与"长期记忆"，此前讨论已触及但不够系统化、理论化。
现状 `is_static` 已做**性质分类 + 召回分流**，但缺**生命周期模型**（晋升 / 衰减 / 遗忘）。
另：用户主场景是"agent 开发与讨论"，痛点"做一件事有很多上下文，回来要重新讲"——这是
**任务/会话级上下文恢复**，与事实级记忆是同一系统的两个召回粒度，本 topic 一并纳入。

## 现状盘点（代码事实）

- `is_static`：schema 注释"静态事实（画像类）vs 动态状态"（ENTITY_DESIGN 同）；`detect_is_static`
  规则判定（偏好/永久特征→True，一次性事件/近期活动→False）；`memory_store` 按 `is_static=TRUE/FALSE`
  分两条召回路径；profile 亦分"静态永久特征 vs 动态近期活动"；
- 已有 `_classification` 元数据（行为规则 vs 临时记录）——碎片化的分类尝试；
- 缺失：晋升规则、衰减/遗忘规则、任务级上下文这一档。

## 讨论要点

- **澄清**：`is_static` 是"事实性质分类"，不是"记忆生命周期"。两者正交：一条"永久特征"（静态）
  天然是长期记忆，但一条"项目决策"（长期有效）不是个人静态特征；"近期/长期"回答的是"什么时点、
  多强地注入"，不是"这条事实是否永久成立"。
- **三层草案**（收敛 is_static / profile 静动态 / `_classification` 碎片为生命周期模型）：
  - **L0 流水/观察层**：原始素材，不注入，只做蒸馏与纠错原料（可后置，先讨论要不要）；
  - **L1 近期/工作记忆**：动态事件 + 任务快照，高时效、衰减快、注入优先；
  - **L2 长期/沉淀记忆**：去重收敛后的稳定事实/决策/偏好，低时效、靠复用 + 确认维持。
- **晋升 L1→L2 条件**：复用次数 / 用户确认 / 跨 session 稳定复现 / confidence 达标；
- **任务级上下文（本次合并的 #5）**：两个消费场景已存在——
  - (a) 新 session 首问**强制注入** = `/context-inject` 的 push（压缩 hook / context-inject）；
  - (b) 新问题**主动 query** = search / MCP 工具；
  "智能（动态大小、动态内容）" = MR-017 cap 配置化 + 召回排序 + 分层优先级 + 置信度。
- **与 MR-006 关系**：分层是"单一事实源"的支撑——"最新事实"的演进需要一份可回看的观察流；
- **与 MR-019 关系**：L0 流水层是蒸馏的原料（文档被移出后，只剩已蒸馏事实，缺原始素材）。

## 结论

暂无结论。方向认可，需系统化后落 ADR；`is_static` 语义需澄清为"性质分类"而非"生命周期"。

## 下一步

1. 澄清 is_static 与分层的关系（性质 vs 生命周期，正交），避免两套概念；
2. 定义三层各自的存储/召回/衰减/晋升规则，作为 MR-006（知识对象）设计的输入；
3. 任务级上下文作为 L1 一等形态设计，与 MR-017 一起定"动态大小/内容"策略。

## 未决问题

- L0 流水层是否引入——风险：重新引入"第二套生命周期"（MR-008 画像缓存教训），需先论证收益；
- 晋升/衰减的具体触发条件与阈值；
- 任务级快照与原子事实的边界：什么提炼成 L2 事实，什么保持 L1 快照；
- is_static 是保留、改造，还是被分层模型吸收。
