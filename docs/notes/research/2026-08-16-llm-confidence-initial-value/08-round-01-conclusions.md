# 08 · round-01 统一理解

## 一句话

**五平台高度收敛：LLM 自报信心不能当概率，只能当弱特征/过滤门槛；冷启动初始置信的主轴是"来源分层先验（provenance prior）"，真正的置信度靠后续证据更新。**

这直接验证了项目已有结论（[memory-confidence](../../2026-08-14-memory-confidence.md)：自报不可当概率），
并把"不用自报之后用什么"这个开放题给出了收敛答案：**来源先验 + 证据结构 + 后续更新**。
五个平台在回答结构上殊途同归（无预设题面下），可信度较高。

## 共识（5/5 平台一致）

| # | 共识 | 关键细节 | 与我们现状的对接 |
|---|------|---------|----------------|
| 1 | **LLM 自报信心不可作为概率** | 过度自信、校准差是系统性偏置（文献一致：Mielke 2022 / Kadavath 2022 / Lin 2023 / Tian 2023 / Spiess 2024 等）；prompt 工程压不下去；且**模型信息量越少的地方越过度自信**——正是最需要记住的项目特有细节（Claude 强提示） | 验证 memory-confidence 已定结论 |
| 2 | **冷启动主轴 = 来源分层先验** | 用户显式 > 用户纠正 > 直白陈述提炼 > 自动推断 > 纯猜测；典型区间 0.85-0.45（各平台给的具体值略有出入但排序一致） | 与我们 v1 的 `source_kind` 权重思路一致，且被外部独立确认 |
| 3 | **自报分数降级为弱特征/门槛** | 只用它拦截极端低分 / 同来源内 ±0.05 级微调；**严禁跨档跳变**（doubao 强提示）；可完全弃用（Grok 允许） | 承接 MR-017"不静默丢弃"——作为门槛拒绝写入需谨慎，另见 B2 |
| 4 | **置信度 = 可更新的起点，不是终值** | "冷启动不存在可靠的写入时刻真值信号"（Claude）；应允许 `证据量=low` + 标记"未验证"；后续用确认/矛盾/复现/引用做贝叶斯或加权更新（ChatGPT: Beta prior；Grok: base+delta 公式；doubao: 带衰减加权计分） | 与我们"内容置信度 = 派生、后续证据更新"完全同向 |
| 5 | **拆维度：内容真实性 ∥ 当前有效性** | ChatGPT: Trust = Confidence × Freshness；Grok: Source/Extraction Reliability（写入时定）∥ Current Validity（随时间更新）；doubao: 环境事实带生命周期、偏好长效 | ⚠️ **与 v1"砍 valid_from/valid_until"有张力**，见冲突 #2 |
| 6 | **置信度定位是"注入/采信权重"非"真值概率"** | doubao 最直白："当前证据下愿意采信并注入上下文的权重"；ChatGPT: 真正优化的是 P(memory causes useful downstream action)；Claude: "在初始不准时依然安全" | 与北极星价值公式（排序启发式、非精确计算）一致 |
| 7 | **证据独立性意识** | ChatGPT 强提示：跨会话 3 次模型"复述"≠ 3 个独立证据；真独立需不同来源（user 陈述 + package.json + lockfile + CI） | ⚠️ 挑战我们"跨 session 稳定复现作为后续信号"的简单用法，见冲突 #3 |

## 冲突 / 待追问点

| # | 冲突 | 双方 | 为什么重要 |
|---|------|------|-----------|
| 1 | **truth discovery / source reliability 学习是否适用于"单用户 + 单来源"场景** | ChatGPT：高度同构、source reliability 可学习（Dawid-Skene）· Claude：明确怀疑前提（多来源交叉印证是核心条件，单用户单来源可能退化成无信号） | 决定"来源可靠性要不要做成可迭代学习的实体统计"，牵动 entity-attributes 的 provenance 建模深度 |
| 2 | **时间有效性（freshness）是否需要独立维度** | 外部三平台（ChatGPT/Grok 明确、doubao 建议时效标签）建议独立 · 我们 v1 已拍板砍 `valid_from/valid_until`（时间失效交给 supersede/复用频率） | 牵动 v1 关键决策；需想清楚"外部建议"与"我们已拍板"是不是同一件事（见下"回项目内核对"） |
| 3 | **跨会话"稳定复现"作为可信度信号的可信度** | ChatGPT：不独立（同一用户+模型复述不算独立证据）· 其余平台：把"跨会话一致"列为强正向信号但未讨论独立性 | 牵动后续信号设计（S-pre 遥测的证据权重），过度依赖会膨胀置信度 |

## 回项目内核对（收敛轮做，两处）

1. **freshness 张力的语义辨析**：外部建议的"当前有效性"对应的是我们 v1 里由谁承载？
   我们砍掉的是"时间区间字段"（valid_from/until），但"现在是否仍成立"仍然存在（由谱系边 + 复用频率承载）。
   外部平台主张的是"内容置信度"内部不要再混入时效维度（即 content_confidence 只答"内容为真"，
   "还成立吗"另算）——这**不违背**我们的拍板，反而可能是一种澄清：content_confidence 应该收敛为
   "P(内容为真)"，把"当前成立"的因子放回召回的 freshness 分量。**待 round-02 后回项目内定夺。**
2. **"跨会话复现"独立性**：我们 memory-confidence 里的"跨 session 稳定复现"是否要加入"来源独立性"限定，
   防止模型自复述导致置信膨胀。**待 round-02 后回项目内定夺。**

## 缺失 / 证据不足

- 一致性采样（多次独立提炼同一段对话）迁移到"记忆提炼"场景的有效性：Claude 明说无直接文献，需自己小实验验证。
- "个人化/项目化（非唯一真值、主观决策类）记忆的置信度校准"研究：Claude 指出是空白，可能是新颖方向。
- 校准（Platt / isotonic / Knowledge Vault 范式）作为中期路径：ChatGPT/Claude/Grok 一致建议，但都承认需要后验标注数据、不解决冷启动。
