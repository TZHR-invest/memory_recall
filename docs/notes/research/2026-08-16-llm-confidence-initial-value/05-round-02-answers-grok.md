## 回答（原文）

**1. “当前有效性”（Current Validity）的冷启动形态与合成方式**

**事实层面**：  
- 现有 agent memory 与 temporal knowledge graph 实践普遍将“内容是否曾经为真”与“该主张在当前时间点是否仍成立”解耦，采用 bi-temporal 模型（valid time + transaction time）。superseded 事实被标记为 invalid，而非删除。  
- 衰减多采用指数/Ebbinghaus 形式，并配合访问强化（usage-reinforced decay）；单纯时间流逝或单纯 recency 窗口都不够。  
- 召回时常见做法是把语义相关性、来源/置信、时间有效性作为独立信号再融合，而非单一分数。

**推理层面（可落地设计）**：

将每条记忆拆为两个独立标量（均 ∈ [0,1]）：

- \(R\) = Source/Extraction Reliability（写入时确定，之后仅在有强证据时缓慢修正）
- \(V\) = Current Validity（随时间与证据动态更新）

**冷启动初始化 \(V_0\)**  
按记忆类型给出保守默认，并显式记录 `valid_from` / `valid_to`（`valid_to = null` 表示仍开放）：

| 记忆类型 | \(V_0\) | 说明 |
|----------|---------|------|
| 用户偏好 / 身份事实 / 显式决策 | 0.90–0.95 | 默认长期有效，除非被纠正 |
| 环境/配置事实（可验证） | 0.80–0.90 | 有明确变更信号时再降 |
| 踩坑与修复记录 | 0.75–0.85 | 默认仍相关，但随项目演进可衰减 |
| 临时观察 / 会话级状态 | 0.50–0.70 | 默认较短有效期 |
| 纯推理 / 推测 | 0.40–0.60 | 低初始有效性 |

同时写入 `last_reinforced_at = created_at`，`access_count = 0`，`contradiction_count = 0`。

**推动 \(V\) 的信号（按优先级）**  

1. **显式 supersession / 矛盾**（最高优先级）  
   新记忆与旧记忆在同一 (subject, relation) 上冲突 → 旧记忆 `valid_to = now`，\(V\) 立即降到 0.05–0.15（保留历史可查）。不依赖相似度阈值。

2. **访问强化（usage reinforcement）**  
   被成功召回并实际注入助手上下文后：  
   \[
   V \leftarrow \min(1,\; V + \alpha \cdot (1-V)),\quad \alpha \approx 0.08\text{–}0.12
   \]  
   并更新 `last_reinforced_at`。这是“仍有用”的最强正向信号。

3. **时间衰减（在无强化时）**  
   采用 usage-reinforced 指数衰减：  
   \[
   V(t) = V_{\text{base}} \cdot \exp\bigl(-\lambda \cdot \Delta t_{\text{days}}\bigr)
   \]  
   其中 \(\Delta t\) 为距 `last_reinforced_at` 的天数；\(\lambda\) 按类型设置（偏好类 \(\lambda\) 小，临时观察 \(\lambda\) 大）。典型 half-life：偏好/决策 60–180 天，踩坑 30–90 天，临时状态 7–21 天。衰减只降低 \(V\)，不直接删除。

4. **被动观察（可选、成本可控）**  
   - 项目文件/配置变更检测到相关实体被修改 → 对该记忆发出“可能失效”信号，\(V\) 下调 0.1–0.2 并标记待复查。  
   - 长期零访问且已过 half-life 的记忆，进入冷存储或降低召回权重。  
   冷启动阶段可先不做主动扫描，只做被动触发。

**召回排序合成（具体形态）**  

推荐**乘法 + 可调下限**，而非简单加权和：

\[
\text{final\_score} = \text{sim}(q,m) \times \bigl(w_R \cdot R + (1-w_R)\bigr) \times \bigl(w_V \cdot V + (1-w_V)\bigr)
\]

更干净、更常用的实现是：

\[
\text{final\_score} = \text{sim}(q,m) \times R^{\beta} \times V^{\gamma}
\]

经验起点：\(\beta = 0.6\)–\(0.8\)，\(\gamma = 0.7\)–\(1.0\)。  
- \(R\) 控制“这条内容本身是否值得信”；  
- \(V\) 控制“现在是否还该用它”。  

乘法保证任一维度接近 0 时最终分数塌缩，避免“高可靠但已失效”或“仍有效但来源极差”的条目挤进 top-k。  
若需要更平滑，可改为：

\[
\text{final\_score} = \text{sim} \times (0.3 + 0.7 R) \times (0.2 + 0.8 V)
\]

（下限防止完全归零，便于调试）。  
召回后再做二次过滤：\(V < 0.15\) 的条目默认不注入，除非用户明确查询历史。

这套形态在冷启动时完全可运行：只依赖写入时的来源类型与时间戳，后续信号逐步填入。

---

**2. 冷启动阶段对自报信心的处理**

**倾向（推理）**：冷启动、无校准数据时，**完全忽略自报信心**，或最多用作同来源内部的极弱排序键，且**绝不进入 \(R\) 的数值**。

理由：  
- 自报信心的校准误差在多种任务上已被反复证实（过自信、ownership bias）。  
- 冷启动没有 ground-truth 可做后处理校准，任何非零权重都会把模型的“复述自信”系统性带入 \(R\)。  
- 同来源内部排序完全可以用其他更稳的信号替代（是否直接引用用户原话、提取一致性、schema 通过率、语言标记）。

**若仍想保留作为同来源内部排序**：  

1. **隔离使用**：只在同一 `source_type` 桶内作为 tie-breaker，不参与跨来源比较，也不写入 \(R\)。  
2. **硬裁剪**：  
   \[
   c_{\text{aux}} = \text{clip}\bigl( (c_{\text{self}} - 0.5) \times 0.06,\; -0.03,\; +0.03 \bigr)
   \]  
   然后仅用于桶内排序：`rank_key = primary_signals + c_aux`。  
3. **防止“模型复述虚高”渗入**：  
   - 若提取结果与用户原话高度重合（编辑距离或 embedding 相似度 > 阈值），强制 \(c_{\text{aux}} = 0\) 或改为“直接引用加分”（来自 provenance，而非自报）。  
   - 要求提取 LLM 同时输出 `extraction_type ∈ {verbatim, paraphrase, inference}`；仅对 `verbatim` 允许极小自报扰动，对 `inference` 直接置 0。  
   - 多次采样一致性优先于单次自报分数：一致性高 → 小幅正扰动；一致性低 → 负扰动或忽略。  

**更干净的做法**：冷启动阶段完全关掉自报通道，把工程精力放在来源先验、语言标记和提取过程特征上。等系统积累了足够的“后续确认/矛盾”数据后，再考虑用这些数据对自报做轻量校准，那时再引入才有意义。

---

**总结（可直接落地）**  
- \(V\) 冷启动按类型给保守默认值 + 开放 valid window；由 supersession（强）、访问强化、时间衰减（弱）驱动。  
- 召回用 \(\text{sim} \times R^{\beta} \times V^{\gamma}\)（或带下限的线性变体）。  
- 自报信心在冷启动阶段建议完全忽略；若保留，严格隔离在同来源桶内且幅度 ≤ ±0.03，并用“是否 verbatim”门控，防止复述虚高进入置信度。  

以上除 bi-temporal 与 Ebbinghaus 衰减的广泛采用属于可观察实践外，具体数值与合成公式均为基于现有模式的工程推理，尚无大规模公开 benchmark 直接验证该精确组合；实施后应用真实项目日志做 A/B 即可快速调参。
