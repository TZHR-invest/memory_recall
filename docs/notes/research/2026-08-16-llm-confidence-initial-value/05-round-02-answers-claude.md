## 一、单用户/单来源场景下，truth discovery 的思想哪些能保留、哪些会退化

先说清楚退化的部分，因为这决定了保留部分的边界在哪里。

### 直接退化、不值得复刻的部分

**1. 迭代式联合估计（EM / 优化算法同时估 source reliability 和 claim confidence）。** 这是 truth discovery 的核心算法机制：如果某个来源的说法经常得到其他来源支持,该来源会被认为更可靠,其信息也因此更可能被判定为真——这个迭代之所以能收敛，依赖的是一个"claim-source 二部图"里有足够的边（同一 claim 被多个来源认领）。你们的典型场景是单用户单次陈述，这张图里几乎没有可以迭代的边，硬套这套算法只是在一个退化图上跑一个不会产生额外信息的计算，不值得投入工程复杂度。

**2. Dependent source / 回声室检测。** 这类方法解决的是"来源之间互相抄袭/传播同一个错误，导致虚假的多数支持"的问题（研究里明确区分独立来源和会互相回声的依赖来源）。你们只有一个来源，这个问题根本不存在，可以直接跳过，不需要为此设计任何机制。

**3. Long-tail 稀疏来源建模。** 这类工作处理的是"极多来源、每个来源只提供少量声明"的稀疏矩阵场景（研究提到大多数来源只提供少量声明、只有少数来源提供大量声明的长尾现象）。你们的"来源"维度本来就只有两三种（用户显式 / 系统提炼 / 用户纠正），没有这个稀疏性问题，这块方法论对你们没有用武之地。

### 可以保留、但需要重新定位的部分

**1.（我认为最有价值的一点）把"来源"拆成"陈述来源"和"提炼过程"两个独立维度，而不是只有一个"来源"。** 这不是我凭空推的类比，是有直接文献支撑的结构：知识融合的原始框架里明确指出，输入是三维的，多出来的一维代表提取器（extractor），矩阵里每个格子代表某个提取器从某个网络来源对某个数据项提取出的内容;错误可以在流程的任何一个环节混入,不仅来自网络来源本身,也来自提取系统的三元组识别、实体链接、谓词链接等环节。

这个结构直接搬得过来：即使"用户"这个来源只出现一次，"LLM 提炼"这个环节本身仍然是一个独立的、可以重复采样的维度。也就是说，**单来源场景下 truth discovery 真正能帮你估计的，不是"用户说的这句话客观上是不是真的"（这个没有第二个独立声音可以验证，本质上无法用重复采样解决），而是"LLM 把用户这次陈述转写成记忆文本的过程中引入了多少提炼误差"。** 这是两个不同层次的不确定性，你们上一轮讨论的"多次独立提炼看语义是否收敛"，本质上就是在测这一层，而不是在测用户陈述的真实性——这个定位上的区分很重要，避免误以为一致性分数能回答"内容是不是事实"这个更难的问题。

**2. 增量式 / 时序真值发现的思路，可以为"跨会话复现"这个你们已有设计提供理论支撑。** 已有工作专门处理"声明按时间陆续到达、真值和来源可信度都在动态演化"的场景，investigate了对象真值和来源可信度之间的时序关系,提出增量式框架,能随着新数据到来动态更新对象真值和来源权重。

把这个思路搬过来：同一用户在不同会话里对同一件事（比如某个环境配置、某个架构决策）多次提及，可以看作**跨时间的弱多源信号**——不是严格意义上"多个独立主体"的交叉验证，但结构上是同构的：每一次提及都是一次新的观测，用来增量修正这条记忆的置信度。这实际上就是你们本来就设计好的"跨会话稳定复现"信号，时序 truth discovery 文献没有给你们全新的东西，但提供了一个更严谨的框架去想清楚"复现次数该怎么累积成置信度"（增量更新、而不是简单计数），如果你们想把"复现次数→置信度"这一步做得更精细，可以参考这类增量更新的形式，而不是自己拍一个线性公式。

**3. "来源类型天然可信度不同"这个直觉可以保留，但估计方式要换。** 不能再指望迭代投票算出来源可信度（没有投票的数据基础），只能退回到我上一轮说的**离线历史统计**：某个来源类型（比如"系统自动提炼"）历史上产生的记忆里，有多少比例最终被验证或被推翻，用这个经验频率做先验。这已经不是严格的 truth discovery 算法，而是它的一个简化残留——诚实地说，这一步退化后，和我上一轮提到的"校准"思路基本重合了，truth discovery 在这里没有提供额外的方法论，只是提供了"来源可信度应该是一个独立于内容可信度、可迭代修正的量"这个概念框架。

**一句话总结这部分：** truth discovery 真正不可替代的机制（多来源投票估计可靠性）在你们场景下用不上；但它"把可信度问题拆解成多个独立维度（来源 vs 提取器 vs 时间）分别处理，而不是揉成一个数"这个建模习惯是值得保留的，哪怕具体算法要换成别的。

## 二、"多次独立提炼语义一致性"的小规模验证实验设计

### 先明确实验要回答的问题

不是"一致性分数高不高"，而是："在控制了更便宜的信号之后，一致性分数对'这条记忆后续是否可靠'还有没有独立的预测力，值不值得付出 N 倍采样成本。" 这个问题设定本身决定了下面的对照组设计不能省。

### 抽样

- 从真实历史对话中抽取会触发记忆提炼的片段，**按记忆类型分层**（结构化可验证事实 / 项目决策 / 用户偏好），不要混合抽样后只看总体指标——我在上一轮的推测是这个信号很可能对"可验证事实"有效、对"主观决策"未必有效，如果分层抽样不做，总体 AUROC 很容易被强的子类型拉高，掩盖弱子类型完全没有信号这个事实，得出过度乐观的结论。
- 抽样时要覆盖"后来证明对的"和"后来证明错的/被推翻的"两类案例，不能只从"看起来正常沉淀下来的记忆"里抽——如果你们历史数据里"被推翻"的案例本来就少，这本身就是个问题（负类样本不足会导致 AUROC 估计方差很大），需要专门去找这类案例，比如用户显式纠正过的记忆、或者已知环境变了导致记忆过期的案例。

### 生成

- 对每个候选片段，用真正独立的采样（不同随机种子/非贪心解码）跑 N 次提炼 prompt，N 建议从 5 起步；用贪心解码重复调用会人为制造虚高的一致性，这个坑一定要避开。
- 语义聚类时要留一个已知弱点的记录：相似度阈值没调好会把"同一意思、不同措辞"误判为不一致，导致虚报低一致性。建议聚类后人工抽查一批被判为"不一致"的案例，确认是真正的语义分歧还是只是措辞差异，否则你们测出来的"信号是否存在"结论可能是被聚类算法的噪声污染的，而不是真实反映了内容本身的不确定性。

### 标签——这是最容易被带偏的一环，也是你问题里最关键的部分

**核心原则：标签必须来自行为性/客观性证据，不能来自"看着这段提炼文本判断像不像真的"这种主观判断。** 理由很直接：一致性分数和"这段文字写得是否流畅自信"如果共享同一个偏差来源（比如都受内容具体性影响），用主观判断当标签会让两者产生虚假的高相关——你在验证一个信号有没有用，不能让验证标准本身携带这个信号想要预测的同一种偏差。

具体做法：
- 最干净的标签：**后续已发生的客观验证结果**——用户是否显式纠正过这条记忆、对可程序验证的内容直接跑代码核实是否仍然成立、这条记忆被召回使用后是否引发了错误或被用户否决。这些不依赖任何人或模型的"感觉"。
- 如果历史数据里这类客观验证结果不够多（冷启动阶段常见），退而用人工标注，但要满足两个条件：（a）标注者看不到一致性分数，盲标；（b）标注协议设计成"你能否在原始对话记录里找到直接支持这句话的证据"这种可核查式问题，而不是"你觉得这句话准不准"这种主观印象式问题——后者本身就容易被语言的流畅自信带偏，这正是你们最初想避开的那个问题，如果标签生产环节又引入了同样的偏差，整个实验就失去了意义。

### 对照组——没有这一步，实验结论没法用

- **对照 A：单次生成时 LLM 自报的置信度分数。** 如果一致性分数的判别力（AUROC）并不明显好于自报分数，那么 N 倍的采样成本不划算，直接得出"不值得做"的结论也是一个有效结果。
- **对照 B：零成本启发式特征**——内容长度、是否包含具体数值/路径（可验证性的廉价代理）、来源类型。如果这些特征已经能达到接近的判别力，一致性采样的边际价值就存疑。
- 只有一致性分数在**控制了 A、B 之后依然对标签有独立预测力**（比如用逻辑回归同时放入这几个特征，看一致性分数的系数是否显著、是否提升了整体 AUROC），才能说这是一个真正有增量价值、值得付费的信号，而不是在重复一个更便宜特征已经能提供的信息。

### 最小样本量——诚实地说，没有一个我能给你的"标准答案"

我没有看到任何文献给出"这类具体设置下最少需要多少样本"的确定数字，这是我基于统计经验给的可操作估计，不是引用：
- 如果你们想得到一个哪怕粗糙、但能给出置信区间的 AUROC 估计（比如宽度在 ±0.1 左右，95% 置信度），经验上正类和负类样本各自需要不少于 50-100 个，也就是总共大约 100-200 个已标注案例作为起步规模。
- 如果只是想做一个"有没有明显趋势"的粗筛（不追求严谨置信区间），30-50 个案例可能就能看出方向，但这时候结论只能当作"值不值得投入做正式实验"的初筛依据，不能当作定论去指导生产系统的设计。
- 按记忆类型分层意味着上面这个样本量要**分别乘以类型数**，不是总量除以类型数——如果你们只有 150 个案例但分三种类型各 50 个，每个子类型的置信区间会很宽，这一点需要在解读结果时留出余地，不要因为某个子类型样本少、没测出显著信号就直接下结论说"这个类型上没用"，有可能只是样本不够。

### 最后一个提醒

即使这个实验做出来"一致性分数确实有独立预测力"，它给你的也只是一个**相关性**结论，不能反推出因果机制（"内容一致 → 内容更可能为真"这个因果方向本身在文献里也不是绝对成立的，尤其是在你们这种非事实性问答的记忆类型上，我在上一轮已经说过这属于从 QA 场景推断迁移，没有直接证据）。如果实验显示有信号，比较负责任的用法是把它当作排序里的一个加权特征，而不是当作可以单独决定"是否写入/是否高危"的判定依据——这个界限的把握，可以对应回你们已有的"高风险内容走低阈值高验证通道"的设计:一致性分数这类偏统计性质的信号，适合做**排序优化**，不适合做**安全判定**。
