# 01 · 背景与目标

> 归属: [README](README.md) 调研卡 · 日期: 2026-08-16

## 背景

我们在做一个 **AI 开发助手的长期记忆系统**。系统在陪伴用户开发项目时，会从对话、用户操作、项目产出里
持续沉淀"记忆条目"（用户偏好、项目决策、环境事实、踩坑与修复等）。之后用户继续开发时，系统把这些记忆
**召回并注入**给助手使用。

我们希望记忆库是"可信的知识"而不是"越来越脏的堆积"。为此系统为每条记忆维护一个
**内容置信度（content confidence）**：这条记忆"内容为真、且当前仍然成立"的概率，用于召回排序，
也让用户能在工作台看到每条记忆的可信程度。

现在的卡点：**写入时刻的"初始置信度"怎么定**。

在设计上，一个看起来很自然的做法是：在系统把一条对话提炼成记忆时，让 LLM 顺便输出一个
"信心分数 / 质量评分"，作为这条记忆的初始置信度。但我们的经验与已有结论是：

- LLM 自报的信心分数**普遍不可靠**：过度自信、校准差——分数高不代表真的更可靠；
- 不同来源的记忆（用户显式要求记住 / 系统自动提炼 / 用户纠正）天然可信度不同；
- 我们已倾向于：自报分数不能当概率用，真正的确定性要靠**后续信号累积**
  （被引用次数、用户确认、跨会话稳定复现），但冷启动时这些信号都是空的。

所以真正的问题是：**冷启动的、写入那一刻的"初始可信度"，到底应该来自哪里、怎么算才可靠？**

## 目标（一句话）

搞清楚：**在长期记忆系统里，写入一条记忆时，如何获得一个可靠的"初始可信度"？**
LLM 在写记忆时自报的信心分数在这个问题上到底能不能用、怎么用才不被它的过度自信带偏；
如果它不可靠，更好的替代思路 / 机制是什么，各自的采集成本与精度如何。

希望从多个平台各自独立的视角出发，得到尽量完整、不被我们预设框架框住的答案。

## 本轮不做什么（不预设红线）

- 不预列候选信号 / 机制清单，不预给初值公式、来源权重、或任何阈值；
- 不点名任何文献 / 理论框架让平台去套；
- 不预先拆分问题：根本问题整体抛给平台，由各平台自行组织；
- 不预先映射回任何实现方案（回项目内验证阶段再做）。
