问题 2：怎么识别 "项目无关、可跨项目复用" 的知识？它和 "项目内" 知识的判据是否不同？区分信号（核心判据：知识是否依赖本项目 / 当前环境）
一句话先给结论：判据底层是同一个（依赖绑定），但判定信号集不同；核心检验：把这条知识直接拿到新项目，是否仍然保真、可直接采信
【原文事实】
腾讯云开发者社区（顾念，2026）Agent 记忆三层划分：短期会话上下文、项目长期规则、项目知识；项目知识绑定代码图谱、接口、设计决策；全局 / 用户级规则（如编码偏好、通用踩坑模式）跨项目可用
URL：https://cloud.tencent.com.cn/developer/article/2684745
掘金（ZengLiangYi，2026）MCP+Claude Code 记忆实践：显式scope:global标记跨项目知识库；沉淀reusable_patterns（可复用模式、根因修复范式）进入全局，项目专属配置 / 路径放项目域
URL：https://juejin.cn/post/7642217352979005459
CSDN OpenMemory Plus（2026）双层记忆路由：项目级记忆（技术栈选型、部署配置、架构决策）vs 用户 / 全局记忆（通用偏好、通用技术范式），路由依据是否绑定项目根目录 / 仓库实体
URL：https://blog.csdn.net/weixin_28733651/article/details/160606872
掘金（七牛开发者，2026）Agent 工程知识沉淀：项目内 Learning 会随代码实体失效；跨项目复用知识必须剥离文件路径、仓库名、实例 ID 这类局部绑定实体，只保留稳定模式与根因逻辑
URL：https://juejin.cn/post/7659740022915072034
【推断】
✅ 底层判据相同：知识真值是否依赖「本项目局部实体 / 环境约定」；但信号清单、失效规则不同
项目内知识：真值绑定项目唯一实体（仓库路径、实例域名、本项目特定架构约束、本次迭代规划、本项目产出物 ID）；换项目直接失效、不可直接采信
跨项目复用知识：真值不依赖本项目实体；只依赖领域通用约束、工具原生行为、通用工程模式、用户长期稳定偏好；迁移到新项目依然成立
可落地区分信号清单（可直接给 LLM 做分类 Prompt）
🔹 【项目内知识信号 → 禁止跨项目复用】出现任意一条即判定
包含项目唯一实体：仓库路径、文件 / 函数名、数据库表名、本项目域名 / 实例 ID、本次迭代版本号、项目专属代号
依赖本项目已锁定决策：“本项目选用 XX 而非 YY”、本项目特定折中约束、本项目排期 / 交付目标、本项目风险清单
局部临时状态：当前未完成计划、待办、本次调试临时结论、仅适配当前环境变量的临时方案
真值随本项目代码 / 文档变更而自动失效
🔹 【跨项目可复用知识信号 → 可入全局记忆】全部满足
断言不引用任何本项目唯一实体；可剥离项目实例依然成立
属于：通用踩坑根因 + 修复范式、工具原生 API 行为、通用架构权衡、用户长期稳定偏好（如默认不使用 ORM、习惯用特定校验方式）、领域标准
失效条件是工具 / 标准版本迭代，而不是本项目修改
可被复用到全新空白仓库，结论不变
简易测试 prompt（工程可用）：
如果把这条知识复制到一个全新空白同领域项目，不加修改，是否依然为真、可以直接采信？
【不知道】
经典知识管理 / AI 记忆领域没有公认、标准化的形式化本体专门定义 “项目绑定知识 vs 通用可复用知识”，上述均为 2025–2026 中文 Agent 工程社区实践，无 ACM/ACL 等权威标准定义。
问题 3：把 "重复输入 / 再获取成本" 作为记忆价值的度量，文献或中文社区笔记 / 知识管理实践里有可操作的近似吗？（复用频率、再获取时间、未来被引用概率）
核心结论：有成熟近似；主流落地是「节省再获取时间 × 未来复用概率」，再辅以复用频次、替代成本（重新检索 / 重新推导的 token / 工时）；Agent 记忆论文和 Zettelkasten/PARA 个人知识管理两条线各自有可操作方案
【原文事实】
A. Agent 记忆（LLM Agent 方向，arXiv）
MemoryCPT（Zhong et al., 2026, arXiv:2608.04843）提出 Quality per Cost（QPC），核心是按「推理 / 检索成本」权衡记忆价值；记忆价值来自避免重复证据搜集、重复推导，直接对应你定义的 “再获取成本”；可近似为：价值 ∝ （不使用该记忆时的再获取开销 − 使用记忆的检索开销）× 未来被查询概率arXiv
URL：https://arxiv.org/html/2608.04843v1
Cognitive Workspace（arXiv:2508.13171v1）使用Memory Reuse Rate（记忆复用率）作为核心指标：同一条记忆在多轮任务中被检索命中的比例，作为价值代理；实验直接对比有无长期记忆下重复研究开销下降幅度arXiv
URL：https://arxiv.org/html/2508.13171v1
LeanMem（Liao et al., 2026）异构记忆调度：写入过滤直接评估替代成本—— 如果丢掉这条记忆，Agent 需要多少额外 token / 工具调用才能重新得到同样结论；替代成本越高，记忆优先级越高
B. 中文社区 PKM / 笔记实践（Zettelkasten、PARA、开发者知识库）
AtlasWorkspace PKM 实践（2026）：把检索耗时（再获取时间）、复用证明（这条笔记是否支撑后续决策 / 产出）作为价值核心；直接对应 “忘记就要重新查、重新整理” 的重复成本；指标：Retrieval Speed（找到旧结论耗时）、Reuse Proof（笔记被复用在产出中的次数）
URL：https://www.atlasworkspace.ai/blog/personal-knowledge-management
掘金 / CSDN 开发者 Agent 记忆社区通用落地（Mem0、MCP 生态）：采用频次 + 替代成本二元打分
复用频次：这条记忆被检索命中 / 被注入上下文的次数
替代成本：用户重新口述一遍 / Agent 重新调用工具推导该结论预估 token / 时间
工程简化：价值得分 ≈ 复用频次 × 预估再获取耗时（或等价 token 成本）
知识管理 ROI 经典口径（Soutron、Coworker AI）：节省工时 = 重复搜索与重复试错减少的时间，是企业 KM 里最成熟的可落地近似；直接把 “不用记忆就要重新找 / 重新试” 的时间换算为价值，和你的价值锚点完全对齐
【推断】
✅ 最适合你这个 Agent 记忆系统的可操作近似（直接产品落地）
价值 Score ≈ P (未来被需要) × C (再获取成本)
P (未来被需要) 代理：历史复用频次、同主题查询密度、知识类型（通用范式 > 临时调试碎片）
C (再获取成本) 代理二选一（按你系统粒度）
人机侧：用户重新输入 / 重新检索到该结论需要的预估时间
Agent 侧：无该记忆时，重新推导 + 工具调用 + 网页检索消耗的token 总量 / 工具轮次
落地规则（工程化，不用复杂预测模型）
基线：新记忆先给基础再获取成本（如 “完整复述这条结论预估 120token/30 秒”）
正向加权：每成功复用一次，小幅提升 P (未来被需要) 权重
衰减：随时间、项目归档、工具版本过期，降低 P；过期知识直接压低分
过滤阈值：Score 低于阈值不持久化长期记忆，只放短期会话上下文
注意：没有文献能直接观测 “真实未来被需要概率”，全部是代理指标（频次、相似查询密度）；这是近似，不是真值。
【不知道】
没有已被广泛标准化、公开标定的数据集，直接拟合 “用户重新输入一条信息的精确耗时分布”；现有论文和社区都是代理指标，没有统一基准真值。
给你产品设计的极简提炼（可直接放进 PRD）
区分跨项目 / 项目内：检验是否绑定本项目唯一实体；底层判据一致、信号清单不同
记忆价值度量：优先用「预估再获取成本 × 历史复用频次」做可操作近似，和你 “忘记就产生重复输入 / 重复检索成本” 的价值锚点完全对齐；Agent 侧可用 token / 工具轮次替代人工时间。
