# 01 · 背景与目标

> 归属: [README](README.md) 调研卡 · 版本: v2（无预设重设版） · 日期: 2026-08-14

## 背景

我们在做一个 AI 开发助手。它会在陪伴用户开发项目的过程中，持续接触并记录大量信息——
用户说过的话、项目产出的内容、项目的现状与规划、开发环境配置、踩坑与修复过程等。

这些信息里，绝大多数是「当下这一次、具体的」，用过就过去了；但其中有一部分，用户希望以后还能
用得上——也许是这个项目稍后还要用，也许是以后做别的项目时也能用。

我们目前**不知道**：

- 依据什么来判断「哪些信息值得被长期留下来、哪些不值得」；
- 这些值得留下来的信息，应该以什么形态、通过什么方式被保存，将来才能真正被复用；
- 从「这一次的具体信息」到「以后长期可复用的东西」之间，到底应该发生什么
  （如果确实需要发生任何转化的话）。

我们不预设上述任何问题的答案，也不预设某个既定框架。

## 目标（一句话）

搞清楚：在一个 AI 开发助手里，**系统应该如何判断并处理它接触到的信息，使得「以后真正需要时
能找得到、用得上」——依据是什么，过程应该怎样。** 希望从多个平台各自独立的视角出发，得到尽可能
完整、而不是被我们预设框架框住的答案。

## 本轮不做什么

- 不预列「候选判据」清单，不预给价值定义或公式；
- 不点名任何文献 / 理论框架让平台去套；
- 不预先拆分问题（题目开放，由各平台自行组织）；
- 不预先映射回任何实现方案（回项目内验证阶段再做）。
