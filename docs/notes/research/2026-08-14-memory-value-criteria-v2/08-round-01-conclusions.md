 # Round 1 统一理解（v2 · 无预设同题）
 
 > 类型: 调研（统一理解） · 调研: 2026-08-14-memory-value-criteria-v2
 > 执行方式: 五平台（ChatGPT / Claude / Grok / Gemini / doubao）收到**同一开放题**，无候选判据、无公式、
 > 无文献点名（v2 与 v1 的关键差异）。回答原文见各 `03-round-01-answers-<platform>.md`，不二次概括。
 > 纪律: 外部回答是素材不是事实；C 类结论回项目内验证后才可进 ADR / 根目录文档。
 
 ## 一、五平台独立收敛的共同结论（无预设条件下出现，可信度高）
 
 本轮最关键的产出：**在不给任何候选判据 / 公式 / 文献的前提下**，五平台独立给出了高度同构的回答。说明以下
 不是题面诱导，而是多平台各自的本质判断：
 
 | 共同结论 | 证据平台（独立提出） |
 |---------|---------------------|
 | 判断标准不是「重要/信息量/新近度」单一维度，而是以**未来复用 / 决策价值**为核心的多维交叉 | 全五平台 |
 | **原始对话不能直接作为长期存储**，必须经历形态转换（提炼 / 结构化 / 抽象） | 全五平台 |
 | 沉淀是一个**生命周期 / 渐进过程**，而非写入时一次性筛选 | ChatGPT（记忆形成=生命周期）、Claude（两阶段）、Grok（持续验证）、Gemini（渐进式抽象）、doubao（完整工作流） |
 | **用户信号 / 确认优先于 AI 自动判断**（AI 只产候选，用户确认/修正为闸门） | ChatGPT、Claude（显式信号）、Grok（建议+用户确认）、Gemini（HITL 隐式/显式）、doubao（用户信号最高权重） |
 | 必须有过时 / 冲突 / 修正机制（版本、衰减、降权、替换，而非只追加） | ChatGPT（evidence+事实vs推论）、Claude（冲突检测+替换）、Grok（过期条件）、Gemini（衰减失效）、doubao（维护机制） |
 | 分层存储：会话级 / 项目级 / 全局级（或事实 / 状态 / 规则） | 全五平台（层级命名不同，结构同构） |
 | 检索时按需激活（JIT）+ 结合当前情境适配，而非全塞 system prompt | Gemini、doubao、Grok、Claude（混合检索）、ChatGPT（未来任务先验） |
 | 默认立场倾向「谨慎沉淀 / 默认不记」，避免记忆污染 | ChatGPT（记忆≠日志）、Claude（默认不记）、Gemini（避免 Context Pollution）、Grok（认知负荷权衡）、doubao（垃圾信息泛滥） |
 
 ## 二、各平台独立提出的「判据」表述（差异在于公式形态，方向同构）
 
 | 平台 | 判据表述 | 是否文献/出处 | 备注 |
 |------|---------|--------------|------|
 | ChatGPT | V(m) = P(future use|m) × Benefit(m) × Cost_forget(m) | 自标「综合推理，不是某篇论文直接提出」 | 明确提升为「未来决策时值得重新进入认知过程的信息」；附 Evidence / 事实vs推论 机制 |
 | Claude | 复用期望值 × 稳定性 × 修正代价 | 自标「自己的推理归纳」 | 修正代价不对称：出错成本 >> 遗忘成本；从 debug log → postmortem → runbook（SRE 实践） |
 | Grok | 跨情境可复用价值 × 未来检索/应用成本 | 综合推理 | 维度：可迁移性 / 决策约束持久性 / 失败修复复用 / 认知负荷权衡 / 用户显式信号 |
 | Gemini | 重搜成本 × 复现频率 × 决策意图(Why) × 抽象潜力 | 部分引用（Park/Shinn/Packer）+ 推理 | 明确反对「Filter at Write」，主张渐进式抽象 + 生命周期 |
 | doubao | 可复用性 / 稳定程度 / 作用域 / 信息类型 / 用户信号 | 部分引用（Generative Agents / ADR）+ 推理 | 5 维度打分，用户信号最高权重；区分「实例 vs 模式」 |
 
 **关键点**：v1 曾把 value ≈ P(future need) × C(reacquisition) 写进 prompt，导致 Q3 结论被批评为「题面循环复读」。
 v2 无预设条件下，ChatGPT 独立推出 V(m)=P×Benefit×Cost_forget，Claude 独立推出「复用期望×稳定性×修正代价」，
 Grok 独立推出「跨情境价值×检索成本」。**这说明「未来价值 × 遗忘/重获成本」这个方向是多平台独立收敛的结果，
 不是题面诱导**——v1 的公式方向被 v2 无预设调研复现，但公式形态（因子构成）各平台存在分歧，仍需追问轮收敛。
 
 ## 三、关键分歧点（round-02 追问轮候选）
 
 | 分歧 | 各方立场 | 处理 |
 |------|---------|------|
 | 价值公式的因子构成 | ChatGPT 三元（P×Benefit×Cost）；Claude 三元（复用×稳定×修正代价）；Grok 二元（跨情境×检索成本）；doubao 五维打分；Gemini 四维 | 方向一致、形态不一。是否需要统一公式 → 追问轮 |
 | 触发时机 | Gemini/doubao：任务节点结束（commit/PR/修 bug）；Claude：信号驱动（显式/纠正/重复引用）；ChatGPT：不能只在写入时决定 | 部分冲突（定时 vs 事件触发）→ 追问轮 |
 | 留存形态 | 规则文件(.cursorrules/CLAUDE.md) / 经验卡片 / ADR / 原子单元 / 未来任务先验——各平台强调不同载体 | 形态命名不同，但都指向「结构化+元数据+可演化」；是否统一为一种主体形态 → 追问轮 |
 | 项目内 vs 跨项目 | doubao/Gemini 明确「默认项目级，全局需显式升级」；Grok 提到跨项目边界；Claude 主张「指针而非内容」（source of truth 留在项目文件） | 方向一致（分层+显式升级），实现细节待项目内验证 |
 
 ## 四、对「问题本身是否问偏」的平台反馈（v2 特意征求）
 
 | 平台 | 反馈 |
 |------|------|
 | Claude | 问题把「哪些值得」和「以什么形态」当成两个先后问题，实际是一体两面，顺序反了会跑偏 |
 | Gemini | 若只看成「写入时筛选」就走偏，核心是渐进式抽象 + 生命周期管理 |
 | ChatGPT | 比「怎么做长期记忆模块」更深一层：从「保存信息」到「形成影响行为的知识/状态」 |
 | Grok | 问题本身未问偏，准确抓住核心瓶颈；补充深化点：多项目/多用户知识归属与冲突、隐私安全 |
 | doubao | 两个隐含预设需警惕：①系统可自主可靠区分（错，需人机协同）②二分法「长期沉淀/丢弃」（错，真实是三层） |
 
 ## 五、round-01 状态与下一步
 
 - **收敛状态**：核心方向（未来价值判据 + 非原始存储 + 生命周期 + 用户闸门 + 分层 + 衰减修正）已达
   「≥2 平台一致」，且是在无预设条件下独立提出，可信度高。
 - **未收敛**：价值公式的因子构成、触发时机、统一留存形态——三者各平台表述不同，属合理分歧，非错误。
 - **建议**：round-02 追问轮只针对上述三分歧点发给相关平台（通常 1-4 条），不再增加平台。
   之后进入收敛轮，回项目内（`apps/api/src/models/` 现有实体、`schema.sql`、`relation_service` 版本链）
   验证映射，再落 99-final-conclusions。
