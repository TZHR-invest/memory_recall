## 目标（一句话）

搞清楚：在一个 AI 开发助手里，**系统如何知道"一条被召回的记忆是否被采纳、有没有用"，从而能反过来
校准哪些记忆值得长期保留**——有哪些信号或机制，各自怎么采集、成本与精度如何。

## 本轮原则（与 v2 相同：只提供背景与目标，不预设）

- 不预列候选信号 / 机制清单，不预给判定公式或"采纳"的定义；
- 不点名任何文献 / 框架让平台去套；
- 不预先拆分问题：同一个开放问题整体抛给全部平台，靠平台自身视角差异求更完整答案；
- 允许并鼓励平台指出"问题本身问偏了"。

## 执行方式

走 RESEARCH_GUIDE 的 Human-in-the-Loop 流程：codex 操作浏览器，把
[02-round-01-prompts.md](02-round-01-prompts.md) 里同一段文本块整块粘贴到每个平台
（ChatGPT / Claude / Grok / Gemini / doubao），回答原文回填到 `03-round-01-answers-<platform>.md`，
不二次概括。纪律不变：出处诚实（事实 / 推理 / 不知道三档 + 给来源）；外部回答是素材不是事实，
C 类结论回项目内验证后才可进 ADR / 根目录。
