区分“低频但有用”与“过时但尚未被揭穿”的记忆，是记忆效用估计中最容易出错的环节之一。 两者在表面上都可以表现为“近期召回次数少、近期正反馈稀疏”，但内在性质截然不同：前者是稀缺高价值经验（例如罕见但致命的踩坑修复、特定环境下的配置约束），后者是曾经正确却已失效的事实或策略。信号层面必须主动构造可区分的证据，而不能仅依赖简单的频率或近期成功率。

1. 信号层面的区分方法

可靠的区分依赖于多维度、跨时间尺度的证据组合，而不是单一指标。以下信号按区分力从强到弱排列（综合文献中的 utility 更新、冲突检测与实践推理）：

冲突与一致性信号（最强区分力）
过时记忆更容易与新出现的证据产生直接或间接冲突：用户明确纠正、代码/环境状态与记忆描述不一致、后续成功路径绕过该记忆、或新记忆与旧记忆在事实层面矛盾。低频有用记忆通常不会产生此类冲突，反而在偶尔被召回时表现出高度一致性（用户接受、问题快速解决、后续无反驳）。
采集方式：维护记忆与近期交互/新写入记忆的嵌入相似度 + 规则/LLM 冲突检测；记录“被纠正次数”与“被绕过次数”。
条件触发与上下文匹配信号
低频有用记忆往往带有明确的触发条件（特定错误信息、特定依赖版本、特定硬件/OS、特定用户目标）。当这些稀有条件再次出现时，记忆被召回并产生正向结果，其条件匹配度高。过时记忆则在条件看似匹配时仍导致失败或被用户忽略。
采集：为记忆附加结构化“适用边界”（applicability constraints），召回时计算匹配分数，并结合结果更新。
恢复与重现价值信号
低频有用记忆在被“重新发现”或被用户主动提及后，通常能迅速产生高价值（一次解决长期困扰）。过时记忆被重新召回后，更容易引发用户困惑或二次纠正。
采集：跟踪记忆被“休眠”后再次被用户或系统激活时的即时效用（接受率、问题解决速度）。
时间衰减与外部世界变化代理信号
过时记忆往往与可观测的外部变化相关（依赖库大版本升级、API 变更、项目架构重构、用户明确声明“已换方案”）。低频有用记忆通常与这些变化解耦。
采集：监控项目元数据变化（package.json、requirements、git 重大提交主题）、用户显式状态更新，作为过时风险的先验。
负反馈的稀疏性与归因质量
对低频记忆，单次负反馈的权重必须显著低于高频记忆。真正过时记忆往往伴随重复性或可归因的失败模式（多次在相似上下文中导致错误）。
实践中：采用“证据阈值”——只有累积到一定数量的、高置信度的负证据后，才显著下调 utility。

综合判断时，建议维护一个多维效用向量（而非标量）：即时效用、长期稳定性、冲突率、条件匹配成功率、外部变化敏感度。低频有用记忆在“稳定性高 + 冲突率低 + 条件匹配时成功率高”区域；过时记忆则落在“冲突率上升或外部变化敏感度高”区域。单纯频率低且近期无正反馈，不足以判定为过时。

2. 保守衰减的具体机制设计

目标是：默认偏向保留（尤其是低频高价值候选），只有在证据充分时才加速遗忘；同时保留快速恢复路径。

衰减速率与函数

采用分段或双时间尺度衰减，而非简单指数衰减。
基础衰减：非常缓慢的时间衰减（例如 utility 每天乘以 0.995–0.998，或按对数时间衰减），保证即使长期不用也不会快速归零。
证据驱动衰减：仅在出现负证据时叠加额外衰减。负证据的权重随证据质量（显式纠正 > 强隐式失败 > 弱忽略）和累积次数非线性增加。

触发条件（何时启动/加速衰减）

必须满足“证据充分”门槛，而非单次事件：
累积冲突次数达到阈值（例如 ≥2–3 次高置信度冲突）；
或在匹配上下文中连续失败且无其他解释；
或外部变化代理信号触发 + 至少一次负反馈。
低频记忆额外保护：召回次数低于某阈值时，负反馈权重打折（例如乘以 0.3–0.5），并延长证据累积窗口。
正向保护：任何高置信度正反馈（尤其是条件匹配下的成功）立即重置或大幅提升 utility，并延长保护期。

恢复路径

快速恢复通道：一旦出现强正证据（用户显式确认有用、在匹配条件下解决关键问题、或人工标记），utility 可跳跃式恢复至接近历史高点，并进入“强化保护期”（短期内大幅降低衰减速率）。
软恢复：即使 utility 较低，只要条件匹配度极高，仍允许以较低优先级被召回（探索性召回），给系统重新验证的机会。
人工覆盖优先：人工操作直接写入高优先级，绕过自动衰减。

整体原则是“慢遗忘、快恢复、证据门槛、低频保护”。这与生物启发记忆中的 reconsolidation 与成熟（maturation）机制方向一致，也符合“宁可多保留一些噪声，也不要误杀稀有高价值经验”的保守立场。

3. 人工可审计接口应暴露的内容

接口的核心目标是：让人在不重训模型、不重新嵌入的情况下，快速定位误判、纠正 utility、调整保留策略，并留下可追溯记录。建议暴露以下结构化信息与操作：

必须暴露的视图与数据

单条记忆的完整档案：原始内容、创建时间、最后更新/召回时间、适用边界（若有）、当前多维效用向量、历史 utility 轨迹图、被召回次数与上下文摘要、所有关联的正/负反馈事件列表（带时间戳、证据类型、置信度、关联会话 ID）。
冲突与证据明细：与该记忆产生过冲突的新记忆或用户纠正原文、冲突检测理由（可解释的摘要）。
衰减状态：当前衰减阶段、最近一次加速衰减的触发原因、保护期剩余时间。
相关记忆簇：语义相近或共享实体的其他记忆，便于批量判断。
召回影响日志：该记忆被注入后的下游结果摘要（用户行为、任务结果、模型是否引用）。

关键操作（即时生效，无需重训）

直接覆盖 utility 分数或多维向量（支持“锁定”防止自动覆盖）。
强制保留 / 强制归档 / 软删除（可恢复的回收站）。
修改或补充适用边界与标签。
标记为“黄金记忆”或“已知过时”，并附带人工理由（写入审计日志）。
批量操作：对某一类记忆（按标签、时间、项目阶段）统一调整衰减参数或 utility。
触发重新评估：对指定记忆重新运行冲突检测或对照生成诊断。
导出/导入：支持将修正后的记忆状态导出为可版本控制的文件，便于跨环境同步与回滚。

审计与可追溯性要求

所有人工操作必须记录操作者、时间、原值、新值、理由，形成不可篡改的审计日志。
提供“影响预览”：修正前模拟该记忆在最近 N 次相关查询中的召回与效用变化。
支持按“最近被自动下调且人工未确认”的记忆做优先审查队列，降低人工负担。

这样的接口把自动系统定位为“提出假设与证据”，把人定位为最终仲裁者。误判发生时，人可以直接改分数、改状态、加保护，系统立即按新状态运行，完全不需要触碰模型权重或重新训练检索器。

以上设计以“证据门槛 + 多维信号 + 保守默认 + 人在回路快速覆盖”为核心，尽量降低误杀低频有用记忆的概率，同时给过时记忆留下被揭穿后的清晰衰减路径。实际参数（衰减系数、证据阈值等）需要在真实开发助手流量上通过 A/B 或离线回放校准；公开文献中尚无针对开发助手场景的完整最优参数集，上述均为基于现有 agent memory 机制与工程约束的综合推理。
