# 产品开发层级完整指南

> **文档说明**：本文档以 Google 搜索为案例，系统讲解产品从需求到实现的完整层级。

---

```
                    ┌─────────────┐
```

## 第 0 层：用户痛点

### 定义

用户在真实生活中遇到的麻烦、困扰、未被满足的需求。

### 核心问题

用户有什么问题需要解决？

### Google 搜索案例

| ID | 用户类型 | 痛点描述 | 场景 |
|----|---------|---------|------|
| P-001 | 研究人员 | 学术资料分散在不同期刊，查找困难 | 需要查阅某领域最新论文 |
| P-002 | 普通用户 | 互联网信息爆炸，找不到想要的内容 | 想买相机但不知道哪个好 |
| P-003 | 学生 | 需要快速找到准确答案 | 作业需要查找资料 |
| P-004 | 商务人士 | 信息时效性差，找不到最新资讯 | 需要了解行业最新动态 |
| P-005 | 开发者 | 技术文档分散，搜索效率低 | 遇到 bug 需要找解决方案 |

**痛点本质**：信息过载 + 信息分散 + 查找效率低

### 痛点特征

- 来自真实场景
- 描述"问题"而非"解决方案"
- 通常用用户的语言表达

## 第 1 层：用户故事

### 定义

从用户视角描述想要的功能，格式为：

> "作为【角色】，我想要【功能】，以便【目的】。"

### 核心问题

用户想要系统能帮他做什么？

### Google 搜索案例

| ID | 用户故事 | 验收标准 | 优先级 |
|----|---------|---------|-------|
| US-001 | 作为研究人员，我想要快速找到某主题的所有学术论文，以便进行文献综述 | 搜索"machine learning"返回相关论文列表 | P0 |
| US-002 | 作为普通用户，我想要搜索结果按相关性排序，以便快速找到最有用的信息 | 前 3 条结果包含我想要的内容 | P0 |
| US-003 | 作为用户，我想要搜索结果包含网页标题、摘要和链接，以便判断是否点击 | 每条结果显示标题+摘要+URL | P0 |
| US-004 | 作为用户，我想要搜索响应时间在 1 秒以内，以便快速获取结果 | 搜索耗时 < 1s | P0 |
| US-005 | 作为用户，我想要搜索框简洁，以便快速输入查询 | 首页只有一个搜索框 | P0 |
| US-006 | 作为用户，我想要看到搜索结果数量，以便了解信息规模 | 显示"找到约 X 条结果" | P1 |
| US-007 | 作为用户，我想要搜索支持多语言，以便搜索不同语言的内容 | 支持中英文等主流语言 | P1 |
| US-008 | 作为用户，我想要高级搜索功能，以便精确筛选结果 | 支持时间、文件类型、站点筛选 | P2 |

### 用户故事 vs 痛点的区别

| 痛点 | 用户故事 |
|------|---------|
| "我总是忘记东西放哪" | "我想要记录物品位置，以便快速找到" |
| 描述问题 | 描述期望的解决方案 |
| 被动 | 主动 |

## 第 2 层：故事线

### 定义

用户完成一个目标所经历的一系列步骤，描述"用户如何使用系统完成任务"。

### 核心问题

用户如何使用系统？

### Google 搜索案例

| 4 | 等待 | 检索+排序+渲染 | 显示加载动画 |
| 5 | 查看结果 | 返回结果列表 | 显示 10 条结果+摘要 |
| 6 | 点击某条结果 | 打开新页面 | 跳转到目标网站 |

#### 故事线 B：高级搜索流程

| 步骤 | 用户行为 | 系统响应 | 界面变化 |
|------|---------|---------|---------|
| 1 | 输入查询 | - | 搜索框显示输入 |
| 2 | 点击"工具" | 展开筛选选项 | 显示时间/类型筛选 |

#### 故事线 C：错误处理流程

| 步骤 | 用户行为 | 系统响应 | 界面变化 |
|------|---------|---------|---------|
| 1 | 输入拼写错误的词 | 检测拼写 | 显示"您是否要搜：xxx" |
| 2 | 输入无结果的关键词 | 返回空结果 | 显示"未找到结果"+ 建议 |

### 故事线 vs 用户故事的区别

| 用户故事 | 故事线 |
|---------|-------|
| "我想要记录记忆" | 记录的完整步骤流程 |
| 单一功能诉求 | 多步骤的交互过程 |
| 静态 | 动态（有时间顺序） |

#### 核心算法设计

**PageRank 算法**：

```
PR(A) = (1-d) + d × Σ(PR(Ti)/C(Ti))

其中：
- PR(A) = 页面 A 的 PageRank 值
- d = 阻尼系数（通常 0.85）
- Ti = 链接到 A 的页面
- C(Ti) = 页面 Ti 的出链数量
```

**查询处理流程**：

```
用户查询
    ↓
┌─────────────┐
│ 查询理解    │ → 分词、纠错、意图识别、实体识别
└──────┬──────┘
       ↓
┌─────────────┐
│ 索引检索    │ → 倒排索引召回、向量检索召回
└──────┬──────┘
       ↓
┌─────────────┐
│ 排序融合    │ → 文本相关性 + PageRank + 语义相关 + 个性化
└──────┬──────┘
       ↓
┌─────────────┐
│ 结果生成    │ → 标题、摘要、富摘要、知识卡片
└──────┬──────┘
       ↓
返回 Top 10 结果
```

#### 数据模型

**网页索引数据模型**：

```
WebPage {
  url: string              // 网页 URL
  title: string            // 网页标题
  content: string          // 网页正文
  links: [string]          // 出链列表
  inlinks: [string]        // 入链列表
  pagerank: float          // PageRank 分数
  last_crawled: timestamp  // 最后抓取时间
  language: string         // 语言
  doc_type: string         // 文档类型
}
```

**倒排索引数据模型**：

```
InvertedIndex {
  term: string             // 词项
  postings: [              // 倒排列表
    {
      doc_id: string       // 文档 ID
      positions: [int]     // 词项位置
      tf: int              // 词频
      weight: float        // 权重
    }
  ]
}
```

## 第 6 层：代码实现

### 定义

根据技术方案编写实际代码。

### 核心问题

代码怎么写？

### Google 搜索案例

#### 关键模块示例

| 模块 | 文件 | 核心类/函数 | 职责 |
|------|------|-----------|------|
| 爬虫 | crawler.go | Crawler, Fetcher | 抓取网页内容 |
| 索引 | indexer.go | Indexer, InvertedIndex | 构建倒排索引 |
| 查询 | query.go | QueryParser, Searcher | 解析查询、执行搜索 |
| 排序 | ranker.go | PageRank, Ranker | 计算网页权重、结果排序 |
| 服务 | server.go | SearchServer | HTTP 服务入口 |

#### 伪代码示例

```go
// 搜索服务入口
func (s *SearchServer) Search(query string) *SearchResult {
    // 1. 查询理解
    parsed := s.queryParser.Parse(query)
    
    // 2. 索引检索
    candidates := s.indexer.Retrieve(parsed.Terms)
    
    // 3. 排序
    ranked := s.ranker.Rank(candidates, parsed)
    
    // 4. 生成摘要
    results := s.generateSnippets(ranked[:10])
    
    return &SearchResult{
        Query:   query,
        Total:   len(candidates),
        Results: results,
        Time:    time.Since(start),
    }
}

// PageRank 计算
func (r *Ranker) ComputePageRank(pages []*WebPage) map[string]float64 {
    pr := make(map[string]float64)
    d := 0.85
    
    // 初始化
    for _, p := range pages {
        pr[p.URL] = 1.0
    }
    
    // 迭代计算
    for i := 0; i < 100; i++ {
        for _, p := range pages {
            sum := 0.0
            for _, inlink := range p.Inlinks {
                sum += pr[inlink] / float64(len(pages[inlink].Links))
            }
            pr[p.URL] = (1-d) + d*sum
        }
    }
    
    return pr
}
```
