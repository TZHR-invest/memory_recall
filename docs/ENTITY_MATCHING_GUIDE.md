# 实体匹配策略使用指南

## 问题背景

### 精确匹配的局限性

传统的实体词典匹配使用**精确字符串匹配**，存在以下问题：

```
查询: "学习了什么新技能"
词典: "新技能学习"
结果: ❌ 匹配失败（字序不同）
```

```
查询: "在咖啡的地方"
词典: "咖啡店"
结果: ❌ 匹配失败（名称不完全一致）
```

```
查询: "技术相关的方案"
词典: "技术方案"
结果: ❌ 匹配失败（插入干扰词）
```

```
查询: "学的新东西"
词典: "新技能学习"
结果: ❌ 匹配失败（语义相似但字面不同）
```

## 解决方案

### 五种匹配策略

| 策略 | 原理 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|---------|
| **精确匹配** | 字符串包含检测 | 速度快、准确率高 | 只能匹配完全包含的字符串 | 查询包含实体名称 |
| **关键词匹配** | 分词后计算关键词重叠率 | 容忍字序变化 | 可能误匹配 | 字序不同但关键词相同 |
| **模糊匹配** | 计算编辑距离（相似度） | 容忍拼写错误、部分匹配 | 性能较慢 | 名称相似但不完全一致 |
| **语义匹配** | 计算 embedding 相似度 | 理解语义相似性 | 需要生成向量，最慢 | 语义相似但字面不同 |
| **正则匹配** | 允许中间插入干扰词 | 容忍插入干扰词 | 可能误匹配 | 查询中插入干扰词 |

### 策略详解

#### 1. 精确匹配（exact）

```python
# 原理：字符串包含检测
查询: "张三的朋友"
词典: "张三"
结果: "张三" in "张三的朋友" → ✅ 匹配成功
```

**优点**：
- ⚡ 速度最快（< 1ms）
- 🎯 准确率最高（无歧义）

**缺点**：
- ❌ 只能匹配查询包含实体名称的情况
- ❌ 字序不同则失败

**适用场景**：
- 实体名称固定
- 查询明确包含实体名称

#### 2. 关键词匹配（keyword）

```python
# 原理：分词后计算关键词重叠率
查询: "学习了什么新技能"
词典: "新技能学习"

查询分词: ["学习", "新技能"]
词典分词: ["新技能", "学习"]

关键词重叠: {"学习", "新技能"}
重叠率: 2/2 = 1.0

结果: ✅ 匹配成功（置信度: 1.0）
```

**优点**：
- ✅ 容忍字序变化
- ✅ 容错性好
- ⚡ 速度较快（5-10ms）

**缺点**：
- ⚠️ 可能误匹配（关键词重叠但不相关）
- ⚠️ 需要设置阈值

**适用场景**：
- 查询和实体名称包含相同关键词
- 字序不同但关键词相同

#### 3. 模糊匹配（fuzzy）

```python
# 原理：计算编辑距离（使用 SequenceMatcher）
查询: "咖啡"
词典: "咖啡店"

相似度 = SequenceMatcher("咖啡", "咖啡店").ratio()
       = 2/3 = 0.67

阈值: 0.6
结果: ✅ 匹配成功（相似度: 0.67）
```

**优点**：
- ✅ 容忍拼写错误
- ✅ 容忍部分匹配
- ✅ 容忍查询是实体的子串

**缺点**：
- ⚠️ 性能较慢（50-100ms）
- ⚠️ 需要设置阈值
- ⚠️ 可能误匹配

**适用场景**：
- 查询和实体名称相似但不完全一致
- 拼写错误、缩写

#### 4. 语义匹配（semantic）

```python
# 原理：计算 embedding 相似度
查询: "学的新东西"
词典: "新技能学习"

查询向量: embed("学的新东西")
词典向量: embed("新技能学习")

余弦相似度 = 0.85

阈值: 0.75
结果: ✅ 匹配成功（语义相似度: 0.85）
```

**优点**：
- ✅ 理解语义相似性
- ✅ 最强鲁棒性
- ✅ 容忍字面完全不同

**缺点**：
- ⚠️ 需要生成 embedding
- ⚠️ 性能最慢（100-500ms）
- ⚠️ 需要预计算实体向量

**适用场景**：
- 查询和实体语义相似但字面不同
- 同义词、近义词

#### 5. 正则匹配（regex）

```python
# 原理：允许中间插入干扰词
查询: "技术相关的方案"
词典: "技术方案"

正则模式: "技.*?术.*?方.*?案"

结果: ✅ 匹配成功（置信度: 0.8）
```

**优点**：
- ✅ 容忍插入干扰词
- ✅ 灵活性高

**缺点**：
- ⚠️ 可能误匹配
- ⚠️ 性能较慢（10-50ms）

**适用场景**：
- 查询中插入干扰词

## 性能对比

| 策略 | 时间复杂度 | 耗时 | 推荐实体数量 |
|------|-----------|------|------------|
| 精确匹配 | O(n) | < 1ms | 1000+ |
| 关键词匹配 | O(n * m) | 5-10ms | 100-500 |
| 模糊匹配 | O(n * m²) | 50-100ms | 10-50 |
| 语义匹配 | O(n * embedding) | 100-500ms | 5-20 |
| 正则匹配 | O(n * pattern) | 10-50ms | 50-100 |

## 最佳实践

### 1. 根据场景选择策略

- **高频查询**：精确匹配 + 关键词匹配
- **重要查询**：关键词 + 模糊 + 语义匹配
- **批量处理**：精确匹配 + 缓存

### 2. 缓存策略

```python
# 缓存常用查询的实体提取结果
entity_cache = {}

def get_cached_entities(query: str):
    if query in entity_cache:
        return entity_cache[query]
    
    entities = extract_entities(query)
    entity_cache[query] = entities
    return entities
```

### 3. 阈值调优

```python
# 根据实际数据调整阈值
FUZZY_THRESHOLD = 0.6  # 模糊匹配阈值
SEMANTIC_THRESHOLD = 0.75  # 语义匹配阈值

```

### 4. 监控指标

```python
# 记录各策略的成功率
metrics = {
    "exact": {"success": 100, "total": 150},
    "keyword": {"success": 80, "total": 100},
    "fuzzy": {"success": 20, "total": 30},
    "semantic": {"success": 15, "total": 20}
}

# 计算成功率
for strategy, data in metrics.items():
    success_rate = data["success"] / data["total"]
    print(f"{strategy}: {success_rate:.2%}")
```
