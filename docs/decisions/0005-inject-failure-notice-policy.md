# ADR-0005: 注入失败提示策略（log + toast，每会话最多 3 次）

> 状态: Accepted
> 日期: 2026-08-12
> 关联: ADR-0003、ADR-0004

## 背景

插件注入失败目前只记日志或静默。用户完全无感知，也难以排查；但把错误写进对话上下文
会污染注入质量，违背记忆系统本职。

## 选项

- A: 仅日志，不打扰；
- B: 每次失败都 toast；
- C: log + toast，每会话最多 3 次，第 3 次提示"后续错误不再显示，详情见日志"，之后静默。

## 决策

选择 **C**，并明确：

- 错误详情只进日志文件（`~/.memory-recall-opencode.log`），不写入对话消息；
- toast 节流按会话维度（`sessionID`）计数，超过 3 次后不再展示；
- toast 本身失败不影响主流程（catch 后继续）。

## 理由

- 可感知与不打扰的平衡：3 次足以让用户知道"记忆注入有问题"；
- 不污染上下文：对话消息是知识资产，错误提示不属于注入内容；
- 用户数量少、自托管，日志路径可查，提示指向日志足够。

## 后果

- 正面：问题可感知、可排查，注入内容纯净；
- 负面：需要会话级节流状态，插件增加少量状态；
- 跟进：节流状态随 `session.deleted` 清理。
