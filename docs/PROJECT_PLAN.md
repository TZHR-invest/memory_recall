## 1. 产品定位（当前事实，2026-08 快照）

**Memory Recall 是一个 AI Agent 的长期记忆系统**：把对话中的事实、偏好与项目文档沉淀为可检索的知识，
在会话/压缩/上下文注入时按需召回，让 AI 跨会话记住用户与项目。

交付形态：

- 后端：FastAPI + PostgreSQL/pgvector，统一 `/context-inject` 召回入口；
- 客户端：OpenCode / DeepSeek TUI / Hermes 三个插件（当前以 OpenCode 为最成熟形态）；
- 观察面：web 仪表盘（stats）+ debug 页面（recall trace）。

### 与早期定位的关系（决策记录）

早期 PRD（archive/requirements.md）定位为"人类记忆 + AI Agent 记忆"双使命，
规划了照片 EXIF、位置记忆、语音输入、人脸识别、need_confirm 等人类记忆功能。
截至 v5.2.3，这些功能均未实现，实际用户与使用场景全部来自 AI Agent 记忆。
**本规划决定：产品叙事收敛为 Agent 记忆系统**；人类记忆愿景冻结，除非重新立项（见 §5）。

## 2. 目标用户与核心场景

| 用户 | 场景 | 系统承诺 |
|------|------|---------|
| AI 开发者 / 重度 Agent 用户 | 跨会话记住用户偏好、项目决策、环境约定 | 记忆自动沉淀 + 按需注入 |
| 项目维护者 | 搁置项目后快速恢复上下文 | 项目文档 + 项目记忆统一召回 |
| 插件使用者 | 压缩/长会话不丢失关键信息 | 压缩前摘要 + 行为指导保留 |

## 3. 产品支柱

1. **记忆**：对话中自动提取事实/偏好/决策，去重、演进（updates/extends/derives）、可遗忘。
2. **文档知识**：项目文档自动导入、分块、向量化，与记忆同入口召回。
3. **知识图谱**：实体 + 实体关系 + 记忆关系，支持关系推理式召回。
4. **统一召回**：`/context-inject` 一路返回画像/记忆/文档，附带 trace 可解释。
5. **可观测性**：recall trace + embedding 日志 + stats，召回质量可调、可证。

## 5. 明确不做（除非重新立项）

- 人类记忆愿景：照片 EXIF、位置记忆、语音 ASR、人脸识别、need_confirm 智能询问；
- 移动端应用、社交/共享记忆；
- 通用知识管理（Notion 式手工整理）；
- 多模态输入（图片/语音/视频作为一等输入）。

这些能力的用户故事与设计历史保留在 `docs/archive/requirements.md` 与 `docs/archive/user-pain-points.md`，
不进入当前路线图。
