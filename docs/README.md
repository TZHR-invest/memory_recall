# Memory Recall - 项目概述

> **文档说明**：本文档介绍 memory_recall 项目的定位、目标和核心功能。

---

## 项目定位

**Memory Recall 是一个通用记忆召回系统**，旨在解决人类记忆痛点和 AI Agent 的上下文限制问题。

### 双重使命

```
┌─────────────────────────────────────────┐
│         Memory Recall 定位              │
├─────────────────────────────────────────┤
│  优先级 1：解决人类记忆痛点             │
│  ├─ 时间追溯：想知道某时间段发生了什么   │
│  ├─ 事件召回：想起一件事但不记得全貌     │
│  ├─ 位置记忆：找东西忘记在哪             │
│  ├─ 照片回忆：看照片忘记在哪拍的         │
│  ├─ 项目延续：项目搁置不知从何下手       │
│  ├─ 健忘问题：年纪大健忘                 │
│  └─ 灵感捕捉：灵感一闪而过忘记           │
├─────────────────────────────────────────┤
│  优先级 2：服务 AI Agent                │
│  ├─ 解决上下文窗口有限问题               │
│  ├─ 解决模型注意力分散问题               │
│  └─ 提供高质量按需召回                   │
└─────────────────────────────────────────┘
```

---

## 核心目标

### 1. 解决人类记忆痛点

| 痛点类型 | 典型场景 | 解决方案 |
|---------|---------|---------|
| 时间追溯 | "上周三我做了什么？" | 时间索引 + 精确过滤 |
| 事件召回 | "记得聊过一个项目，但不记得细节" | 语义搜索 + 关键词召回 |
| 位置记忆 | "钥匙放哪了？" | 位置索引 + 时间排序 |
| 照片回忆 | "这张照片在哪拍的？" | 图片处理 + EXIF 提取 |
| 项目延续 | "这个项目之前做到哪了？" | 标签索引 + 项目关联 |
| 健忘问题 | "我刚要说啥来着？" | 最近记忆快速召回 |
| 灵感捕捉 | "有个好想法但忘了" | 语音/文本快速记录 |

### 2. 服务 AI Agent

| Agent 痛点 | 传统方案 | Memory Recall 方案 |
|-----------|---------|-------------------|
| 上下文窗口有限 | 全量注入，浪费 token | 按需召回，精准注入 |
| 模型注意力分散 | 长上下文稀释关键信息 | 只召回相关信息 |
| 记忆写入不稳定 | 依赖模型主动性 | 自动结构化提取 |
| 记忆召回被动 | 等待模型意识到需要搜索 | 主动推送相关记忆 |

## 主要功能

### 1. 多模态输入

**Phase 1 支持**：
- ✅ **文本输入**：直接输入文字记录记忆
- ✅ **图片输入**：自动提取 EXIF、OCR、场景识别、人脸识别

**Phase 2 支持**：
- 🔜 **语音输入**：ASR 转文本后处理

**暂不支持**：
- ❌ **视频输入**：技术复杂度高，暂不实现

### 2. 结构化存储

**核心设计理念**：完全结构化 + 大模型自动提取 + 关键字段询问

```json
{
  "id": "mem_abc123",
  "content": "今天在咖啡店遇到老同学，聊了很久",
  "created_at": "2026-03-19T00:10:00Z",
  "time": {
    "value": "2026-03-19T14:30:00+08:00",
    "source": "inferred",
    "confidence": 0.8
  },
  "location": {
    "name": "咖啡店",
    "latitude": null,
    "longitude": null,
    "need_confirm": true
  },
  "people": [
    {
      "name": "老同学",
      "person_id": null,
      "need_confirm": true
    }
  ],
  "emotion": {
    "value": "开心",
    "confidence": 0.7
  },
  "tags": ["社交", "友谊", "聊天"],
  "attachments": []
}
```

### 3. 智能召回

**多维度检索**：

| 检索方式 | 适用场景 | 实现方式 |
|---------|---------|---------|
| 时间范围查询 | "上周发生了什么" | 时间索引 + 范围过滤 |
| 关键词匹配 | "和老同学相关的记忆" | 倒排索引 |
| 语义相似度 | "最近开心的事" | 向量索引 + 余弦相似度 |
| 人物关联 | "和张三相关的事" | 人物索引 |
| 位置查询 | "在咖啡店的记忆" | 位置索引 |
| 混合检索 | 复杂查询 | 多索引融合 + 排序 |

**多因子排序**：

```
score = w1 × 时间相关性 (0.3)
      + w2 × 关键词匹配度 (0.3)
      + w3 × 语义相似度 (0.3)
      + w4 × 访问频率 (0.1)
```

## 与现有系统的对比

### 对比 OpenClaw 内置记忆系统

| 维度 | OpenClaw Memory | Memory Recall |
|------|----------------|---------------|
| **存储方式** | Markdown 文件 | 结构化数据库 |
| **写入机制** | Memory Flush（不稳定） | 自动结构化提取 |
| **召回方式** | 全量注入 + 向量搜索 | 按需召回 + 多索引 |
| **维护成本** | 需手动精简 | 自动维护索引 |
| **多模态** | 仅文本 | 文本 + 图片 + 语音 |
| **适用场景** | AI Agent 记忆 | 人类记忆 + Agent 记忆 |

### 核心优势

1. **按需召回**：不再全量注入，节省 token，提高精度
2. **主动推送**：基于上下文主动推送相关记忆
3. **多模态**：支持文本、图片、语音多种输入
4. **结构化**：完全结构化存储，支持精确查询
5. **低维护**：自动提取、自动索引、自动维护

## 项目价值

### 对人类用户

- **解放记忆负担**：不用担心忘记，随时可以召回
- **提高工作效率**：快速找到项目上下文，无缝延续
- **增强生活体验**：记录美好瞬间，随时回顾

### 对 AI Agent

- **突破上下文限制**：无限记忆容量
- **提高输出质量**：精准召回相关信息
- **降低成本**：按需注入，减少 token 消耗
