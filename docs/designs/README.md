# 设计文档（Designs，版本化）

> 状态: ACTIVE · 最后更新: 2026-08-12

存放产品/功能设计：方案、权衡、接口、影响面。
规则见 [docs/DOCUMENTATION_GUIDE.md](../DOCUMENTATION_GUIDE.md#4-设计文档designs版本化)。

## 结构

一个主题一个子目录：

```
docs/designs/<topic-slug>/
├── v1.md        # 第一版设计
├── v2.md        # 第二版（v1 被取代时）
└── LATEST.md    # 指向当前生效版本（指针 + 摘要）
```

领域级设计（实体模型、部署等）直接放 docs/ 根目录（当前生效），
变更时在文档内更新版本号并记录变更原因。

## 模板

```markdown
# <主题> 设计文档 vN

> 状态: 草稿 | 生效 | 被取代
> 版本: vN
> 最后更新: YYYY-MM-DD
> 关联: ADR-xxxx / MR-xxx（可选）

## 背景与目标

## 方案

## 权衡（备选方案与取舍）

## 影响面（数据模型 / API / 插件 / 文档）

## 验收标准

（可验证的清单：每个行为/接口/边界写一条；实现完成后逐条打勾回填结果）

## 实施要点
```

## 约定

- 同一主题**只能有一个生效版本**；新版本产生时旧版本标记"被取代"并保留；
- 设计实现后保持"生效"并标注实现版本/commit；实现偏离设计时更新设计或发新版本，
  不允许文档与代码长期撒谎；
- LATEST.md 只做指针与摘要，不复制正文。
- 一个 Feature 的完整文档流见 [DOCUMENTATION_GUIDE.md §5](../DOCUMENTATION_GUIDE.md#5-一个-feature-的完整文档流)。
