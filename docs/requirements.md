## 一、执行摘要

### 产品定位

**Memory Recall** 是一个通用记忆召回系统，旨在帮助用户记录、管理和召回记忆。产品优先解决人类记忆痛点，同时为 AI Agent 提供高质量上下文召回能力。

### 核心价值

| 价值点 | 描述 |
|-------|------|
| **不遗忘** | 快速记录发生的事件，确保重要信息不丢失 |
| **可找回** | 支持模糊查询、语义搜索，即使只记得片段也能找回 |
| **可恢复** | 项目搁置后能快速恢复上下文，节省 1-2 小时梳理时间 |
| **零负担** | 自动结构化提取，无需手动整理 |

### MVP 目标

- **时间周期**：1-2 周
- **核心流程**：文本输入 → 结构化提取 → 存储 → 查询召回
- **目标用户**：知识工作者、创作者

## 二、问题陈述与目标用户

### 2.1 核心痛点

| 优先级 | 痛点 | 描述 | 目标用户 | MVP 包含 |
|-------|------|------|---------|---------|
| P0 | 事件/信息遗忘 | 想起某件事但不记得全貌，想不起具体细节 | 知识工作者 | ✅ |
| P0 | 灵感捕捉 | 灵感一闪而过，没有及时记录，之后再也想不起来 | 创作者 | ✅ |
| P1 | 项目上下文恢复 | 项目搁置一段时间后，不知道从哪里继续 | 项目负责人 | ✅ |

### 2.2 目标用户画像

#### 主要用户群体

| 用户群体 | 特征 | 核心诉求 | 使用频率 |
|---------|------|---------|---------|
| **知识工作者** | 25-45岁，互联网/科技/咨询行业，每天处理大量信息 | 灵感捕捉、项目上下文恢复、会议记录 | 高频（每日） |
| **创作者** | 写作者、设计师、产品经理，需要捕捉灵感和想法 | 灵感捕捉、素材积累、创作上下文 | 高频（每日） |
| **项目负责人** | 同时管理多个项目，经常需要切换上下文 | 项目进展追踪、搁置项目恢复 | 中频（每周） |

#### MVP 阶段目标用户

**首选用户：知识工作者 + 创作者**

选择理由：
1. 痛点最强烈，愿意为解决方案付费
2. 技术接受度高，能快速上手
3. 使用频率高，能提供持续反馈
4. 场景明确，功能边界清晰

### 2.3 用户现有方案分析

| 方案 | 使用场景 | 优点 | 缺点 |
|------|---------|------|------|
| **手机备忘录** | 记录想法、待办 | 简单、随手可用 | 无结构、难检索、无时间线 |
| **微信发给自己** | 快速记录 | 最顺手、不切换应用 | 信息碎片化、难以整理、容易淹没在聊天中 |
| **纸质笔记本** | 会议记录 | 书写体验好、便于思考 | 无法搜索、携带不便、容易丢失 |
| **Notion/飞书** | 项目文档 | 功能强大、协作友好 | 过于复杂、记录门槛高、不适合随手记 |
| **印象笔记/有道云** | 知识管理 | 分类清晰、搜索好用 | 结构化程度低、需要手动整理 |

### 2.4 现有方案的核心问题

| 问题 | 具体表现 | 用户原话 |
|------|---------|---------|
| **记录门槛高** | Notion 打开要 5 秒，想记的时候已经忘了 | "等打开 Notion，灵感已经跑了" |
| **记录无结构** | 备忘录记了一堆，但找的时候找不到 | "我记得记过，但不知道记在哪了" |
| **检索效率低** | 只能关键词搜索，模糊描述找不到 | "我记得是关于什么的，但想不起具体词" |
| **信息碎片化** | 微信、备忘录、笔记本散落各处 | "到处都记，到处都找不到" |

### 2.5 产品差异化定位

| 维度 | 现有方案 | Memory Recall |
|------|---------|---------------|
| **记录速度** | 打开应用 → 找到笔记 → 输入 | 打开 → 输入（2 步完成） |
| **信息结构** | 纯文本，需要手动整理 | 自动提取时间/地点/人物/标签 |
| **检索方式** | 关键词搜索 | 语义搜索 + 时间范围 + 人物关联 |
| **信息关联** | 孤立记录 | 自动关联时间线、人物、项目 |
| **目标用户** | 所有人 | 知识工作者、创作者（深度用户） |

### FR-1: 文本输入处理

#### FR-1.1: 文本输入界面

**需求描述**：用户可通过文本输入框快速记录事件或想法。

**详细规格**：

| 规格项 | 要求 |
|--------|------|
| 输入框自动聚焦 | 打开页面后光标自动定位到输入框 |
| 字符限制 | 最多 500 字符 |
| 发送方式 | 点击发送按钮或按 Enter 键 |
| 响应时间 | < 1 秒显示"已记录"确认 |
| 多行支持 | 支持 Shift+Enter 换行 |

**用户故事追溯**：
- US-1.1.1: 通过文本输入记录事件
- 痛点: 事件/信息遗忘

**验收标准**：

```gherkin
Feature: 文本输入界面
  
  Scenario: 成功提交文本记录
    Given 用户已登录系统
    And 输入框显示在页面中央
    When 用户输入"今天下午和产品团队开会讨论新功能"
    And 用户点击发送按钮
    Then 系统显示"已记录"确认消息
    And 响应时间 < 1 秒
    And 返回记忆 ID (格式: mem_xxx)
  
  Scenario: 输入超长文本
    Given 用户已登录系统
    When 用户输入超过 500 字符的文本
    Then 系统显示字符计数提示 "已输入 X/500 字符"
    And 发送按钮禁用

  Scenario: 输入为空
    Given 用户已登录系统
    And 输入框为空
    Then 发送按钮禁用
```

**优先级**：P0 (Must Have)

**依赖**：FR-3.1 (记忆持久化存储), FR-2.1-2.5 (结构化提取)

### FR-2: 结构化信息提取

#### FR-2.1: 时间信息提取

**需求描述**：从用户输入的文本中自动提取时间信息。

**详细规格**：

| 规格项 | 要求 |
|--------|------|
| 明确时间提取 | "今天下午3点" → 2026-03-19T15:00:00 |
| 相对时间计算 | "昨天"、"上周一"、"三天前" → 转换为具体日期 |
| 推断时间 | "下班后"、"午饭时" → 推断为合理时间段 |
| 置信度评分 | 输出置信度 0-1，低于 0.7 标记 `need_confirm` |

**用户故事追溯**：
- US-1.2: 自动提取结构化信息
- 痛点: 事件/信息遗忘

**验收标准**：

```gherkin
Feature: 时间信息提取
  
  Scenario: 提取明确时间
    Given 用户输入"今天下午3点开会"
    When 系统执行结构化提取
    Then 提取结果 time.value = "2026-03-19T15:00:00"
    And time.source = "extracted"
    And time.confidence > 0.8
  
  Scenario: 计算相对时间
    Given 用户输入"昨天的会议"
    When 系统执行结构化提取
    Then 提取结果 time.value = "2026-03-18"
    And time.source = "calculated"
    And time.confidence > 0.7

  Scenario: 推断模糊时间
    Given 用户输入"下班后的聚会"
    When 系统执行结构化提取
    Then 提取结果 time.value 推断为工作时间后
    And time.source = "inferred"
    And time.confidence < 0.7
    And time.need_confirm = true
```

**优先级**：P0 (Must Have)

#### FR-3.2: 时间索引构建

**需求描述**：为记忆数据构建时间索引，支持时间范围查询。

**详细规格**：

| 规格项 | 要求 |
|--------|------|
| 索引字段 | time.value (TIMESTAMP WITH TIME ZONE) |
| 索引类型 | B-tree 索引 |

### B. 术语表

| 术语 | 定义 |
|------|------|
| **记忆 (Memory)** | 用户记录的事件、想法或灵感，是系统的核心数据单元 |
| **结构化提取 (Structured Extraction)** | 使用 LLM 从文本中提取时间、位置、人物、标签等结构化信息 |
| **语义搜索 (Semantic Search)** | 基于向量相似度的模糊搜索，支持自然语言查询 |
| **召回 (Recall)** | 根据查询条件检索相关记忆的过程 |
| **索引 (Index)** | 为提高查询效率而构建的数据结构 |
| **向量嵌入 (Embedding)** | 将文本转换为固定维度的数值向量，用于语义搜索 |
| **项目上下文 (Project Context)** | 与特定项目相关的所有记忆和进展信息 |
| **灵感 (Inspiration)** | 用户记录的创意想法，类型特殊的记忆 |
