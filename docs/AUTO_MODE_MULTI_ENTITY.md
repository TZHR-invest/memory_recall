# Auto 模式在多实体和无实体场景下的处理

## 核心区别

需要区分两个层面的"模式"：

### 1. 实体提取阶段的 Auto 模式

```python
enhanced_mode="auto"  # 实体提取策略
```

**作用**：决定如何从查询中提取实体

### 2. 图谱召回的处理逻辑

**作用**：决定如何使用提取到的实体

---

## 关键结论

### 多个实体时

```
实体提取阶段（Auto 模式）:
查询: "张三和李四在咖啡店"
    ↓
精确匹配 → 找到: ["张三", "李四", "咖啡店"]
    ↓
返回 3 个实体（提前终止）

图谱召回阶段（与模式无关）:
OR 条件查询所有实体的关系
```

**结果**：✅ Auto 模式在精确匹配阶段就找到了所有实体，不会继续尝试其他方法

### 无实体时

```
实体提取阶段（Auto 模式）:
查询: "最近开心的事情"
    ↓
精确匹配 → 未找到
    ↓
关键词匹配 → 未找到
    ↓
模糊匹配 → 未找到
    ↓
语义匹配 → 未找到
    ↓
返回 [] （空列表）

图谱召回阶段:
if not entities:
    return {"relations": [], "memories": []}
```

**结果**：❌ Auto 模式尝试了所有方法，仍无实体，图谱召回失败

---

## 详细流程对比

### 场景 1: 多个实体 + Auto 模式

```python
# 查询
query = "张三和李四在咖啡店做了什么"

# 实体提取（Auto 模式）
entities = await extract_entities_from_query(
    query,
    enhanced_mode="auto"
)

# 执行流程
"""
步骤 1: 精确匹配（1ms）
查询: "张三和李四在咖啡店做了什么"
词典: ["张三", "李四", "咖啡店"]

检测:
- "张三" in query? ✅ 找到
- "李四" in query? ✅ 找到
- "咖啡店" in query? ✅ 找到

结果: ["张三", "李四", "咖啡店"]

⭐ 提前终止（Auto 模式特性：找到就停）
"""

# 图谱召回
result = await graph_recall(entities)
# OR 条件查询所有实体的关系
```

**Auto 模式的智能之处**：
- 在第一步（精确匹配）就找到了所有实体
- **提前终止**，不会浪费时间尝试其他方法
- 总耗时：~1ms（仅精确匹配）

---

### 场景 2: 无实体 + Auto 模式

```python
# 查询
query = "最近开心的事情"

# 实体提取（Auto 模式）
entities = await extract_entities_from_query(
    query,
    enhanced_mode="auto"
)

# 执行流程
"""
步骤 1: 精确匹配（1ms）
词典中无匹配实体

步骤 2: 关键词匹配（10ms）
查询分词: ["最近", "开心", "事情"]
词典实体分词: ["张三", "李四", ...]

关键词重叠: 无
结果: 未找到

步骤 3: 模糊匹配（50ms）
查询片段 vs 词典实体
相似度 < 阈值
结果: 未找到

步骤 4: 语义匹配（200ms）
语义相似度 < 阈值
结果: 未找到

⭐ 尝试了所有方法，仍无实体
"""

# entities = []

# 图谱召回
result = await graph_recall(entities)
if not entities:
    return {"relations": [], "memories": []}
```

**Auto 模式的智能之处**：
- **渐进式尝试**：先快后慢
- **不放弃**：尝试了所有方法
- **耗时控制**：虽然尝试了所有方法，但按需执行

---

## 对比：不同模式的表现

### 多个实体查询："张三和李四在咖啡店"

| 模式 | 实体提取策略 | 找到实体 | 耗时 |
|------|------------|---------|------|
| `exact` | 仅精确匹配 | ✅ 3 个 | 1ms |
| `keyword` | 精确 + 关键词 | ✅ 3 个（精确阶段找到） | 1ms |
| `auto` | 渐进式 | ✅ 3 个（精确阶段找到） | 1ms |
| `full` | 全部方法 | ✅ 3 个（精确阶段找到） | 1ms |

**结论**：多个实体时，所有模式都在精确匹配阶段就找到了，性能相同。

---

### 无实体查询："最近开心的事情"

| 模式 | 实体提取策略 | 找到实体 | 耗时 | 图谱召回 |
|------|------------|---------|------|---------|
| `exact` | 仅精确匹配 | ❌ 0 个 | 1ms | ❌ 失败 |
| `keyword` | 精确 + 关键词 | ❌ 0 个 | 11ms | ❌ 失败 |
| `auto` | 渐进式尝试 | ❌ 0 个 | 261ms | ❌ 失败 |
| `full` | 全部方法 | ❌ 0 个 | 261ms | ❌ 失败 |

**结论**：无实体时，所有模式最终都找不到实体，图谱召回都会失败。区别在于：
- `exact` 模式：最快失败（1ms）
- `auto` 模式：尝试了所有方法后失败（261ms）

---

## 关键问题：Auto 模式在无实体时值得吗？

### 问题

```
查询: "最近开心的事情"

Auto 模式耗时: 261ms（尝试了所有方法）
最终结果: 无实体，图谱召回失败

值得吗？
```

### 答案

**值得！** 原因：

#### 1. 混合召回兜底

```python
# 混合召回（推荐）
result = await hybrid_recall(
    query="最近开心的事情",
    user_id="test_user"
)

# 并发执行
tasks = [
    vector_recall(query),   # ✅ 成功（100ms）
    keyword_recall(query),  # ✅ 成功（10ms）
    graph_recall(query),    # ❌ 失败（261ms）
]

# 总耗时: max(100ms, 10ms, 261ms) ≈ 261ms（并发）
# 召回结果: 向量 + 关键词召回的记忆
```

#### 2. 召回率提升

```
如果只用精确匹配:
- 耗时: 1ms
- 结果: 无实体，图谱召回失败
- 召回率: 0%

使用 Auto 模式 + 混合召回:
- 耗时: 261ms（并发，不额外增加）
- 结果: 无实体，但向量/关键词召回成功
- 召回率: 95%+
```

#### 3. 性能优化

```python
# 并发执行，耗时取最大值
总耗时 = max(
    vector_recall_time,    # 100ms
    keyword_recall_time,   # 10ms
    graph_recall_time      # 261ms
) = 261ms

# 不是累加
# 错误理解: 100ms + 10ms + 261ms = 371ms ❌
```

## 最佳实践

### 1. 生产环境推荐

```python
# 混合召回 + Auto 模式
result = await recall_service.search(
    query="最近开心的事情",
    user_id="test_user",
    enable_graph=True,  # 启用图谱召回
    # enhanced_mode 默认为 "auto"
)
```

**优势**：
- Auto 模式尽力提取实体
- 图谱召回失败不影响其他召回
- 并发执行，性能无损
- 召回率最高

### 2. 性能优先场景

```python
# 明确不需要图谱召回
result = await recall_service.search(
    query="最近开心的事情",
    user_id="test_user",
    enable_graph=False  # 禁用图谱召回
)
```

**优势**：
- 不尝试实体提取
- 只用向量 + 关键词召回
- 耗时：~110ms

### 3. 成本控制

```python
# 限制 Auto 模式的尝试范围
entities = await extract_entities_from_query(
    query=query,
    user_id=user_id,
    enhanced_mode="keyword"  # 只用精确 + 关键词
)

# 耗时: ~11ms（避免昂贵的模糊/语义匹配）
```

## 总结

### Auto 模式的行为

| 查询类型 | Auto 模式行为 | 结果 |
|---------|-------------|------|
| 多个实体 | 精确匹配阶段找到，提前终止 | ✅ 快速找到 |
| 单个实体 | 精确匹配阶段找到，提前终止 | ✅ 快速找到 |
| 无实体 | 尝试所有方法后失败 | ❌ 耗时但尽力 |

### 图谱召回的处理（与模式无关）

| 实体数量 | 图谱召回行为 | 结果 |
|---------|------------|------|
| 多个实体 | OR 查询所有关系 | ✅ 召回成功 |
| 单个实体 | 查询单个关系 | ✅ 召回成功 |
| 无实体 | 直接返回空 | ❌ 召回失败 |

### 混合召回的容错

```
无实体时:
图谱召回 ❌ → 自动降级 → 向量 + 关键词召回 ✅
```

### 一句话总结

**Auto 模式在实体提取阶段渐进式尝试，找到就停；图谱召回在多个实体时 OR 查询，无实体时失败但混合召回兜底。**
